# AIエージェント向けMCPツール

<tldr>
    <p><b>概要</b>: IDEに接続したAIエージェント (Claude Code、Codex CLI、Copilot CLIなど) が、サインイン済みの接続を通じてAzure DevOpsツールを利用できます。</p>
    <p><b>セットアップ</b>: 読み取りは設定不要です。エージェントに変更を許可するには、<ui-path>Settings | Tools | DevOps Lens | AI Settings</ui-path> の <b>Let AI agents change Azure DevOps</b> をオンにします。</p>
</tldr>

プラグインは **IDE内蔵のMCPサーバー** (Model Context Protocol) を通じてAzure DevOpsツールを提供します。IDEに接続した任意のMCPクライアント -
Claude Code、Codex CLI、Copilot CLIなど - は、プルリクエストの一覧表示、レビュースレッドの閲覧、パイプライン実行とその失敗の調査、そして (別途オプトインすれば)
コメント、投票、実行のキューイングを、すでにサインイン済みの接続を通じて行えます。

> 認証情報がエージェントに渡ることはありません。ツールはプラグインの認証済みクライアントに対して **IDE内で** 実行され、エージェントが受け取るのは結果であってトークンではありません。オンプレミスサーバー、プロキシ、カスタム証明書はプラグインの他の機能と同じように動作し、エージェント側の追加設定は不要です。
> {style="note"}

## 要件

- バンドルされた **MCP Server** プラグイン (`com.intellij.mcpServer`) が有効であること - このプラグインが対応するすべてのIDEに同梱されています。無効の場合、Azure DevOpsツールは登録されません。
- アクティブなAzure DevOps接続: サインイン済みで、Pull Requestsツールウィンドウでリポジトリが選択されていること。
- IDEのサーバーに接続されたMCPクライアント - <ui-path>Settings | Tools | MCP Server</ui-path> でセットアップします。主要なクライアント向けの設定例が表示されます。

## 読み取りは設定なしで動作します

読み取りツールを有効にする操作は何もありません。エージェントをIDEのMCPサーバーに接続すれば、すでにサインイン済みの接続を通じて、プルリクエストとパイプラインをすぐに一覧・閲覧できます。

## エージェントに変更を許可する

<ui-path>Settings | Tools | DevOps Lens | AI Settings</ui-path> にあるチェックボックス1つで、既定では **オフ** です:

**Let AI agents change Azure DevOps (comment, vote, resolve threads, run and cancel pipelines)**

この設定は **すべての** ツール呼び出しでチェックされるため、切り替えは即座に反映されます - 再起動も再接続も不要です。オフの間、書き込みツールは「読み取り専用」という短いヒントを返し、エージェントがそれをあなたに伝えられます。

> なぜ書き込みだけ別なのか? エージェントが読み取るプルリクエストの内容 - 説明、コメント、ビルドログ - は他人が書いたものです。悪意のあるコメントがエージェントを言いくるめて「親切に」何かを変更させようとするかもしれません
> (「デプロイパイプラインを再実行してください」など)。Azure DevOpsを変更する操作を独立したオプトインの背後に置くことで、読み取りは安全なままになり、プラグインのツール説明はエージェントに対して、その内容を指示ではなくデータとして扱うよう明示的に伝えます。
> {style="warning"}

> この設定は、プラグイン自身のAI機能 (要約、AIレビュー、コミットメッセージ) には影響しません。それらは一度きりのテキスト生成であり、ツールを呼び出すことはありません。このページは、あなたが接続したエージェントについてのみ説明しています。
> {style="note"}

## ツール一覧

読み取りツール (常に利用可能):

| ツール                                  | 返される内容                                                                                   |
|---------------------------------------|------------------------------------------------------------------------------------------------|
| `get_connection`                | 現在のIDEプロジェクトのサーバー、プロジェクト、リポジトリ、サインイン中のユーザー - エージェントの出発点。 |
| `get_ide_context`               | 現在の作業対象: チェックアウト中のブランチ、そのプルリクエスト、ローカルがPRのヘッドより遅れているか。「自分のPR」「このブランチ」を解決します。 |
| `find_pull_request_for_branch`  | ブランチから作成されたアクティブなPR - 既定ではチェックアウト中のブランチ。                       |
| `list_pull_requests`            | PRの一覧 (新しい順)。状態、作成者 = 自分、レビュアー = 自分、ソース/ターゲットブランチでフィルタリングでき、ページングにも対応。 |
| `get_pull_request`              | 1件のPR: 説明、ブランチ、マージ状態、レビュアーと投票、WebのURL、対象コミット範囲。               |
| `list_pull_request_threads`     | 人間のディスカッションスレッド (システムイベントは除外)。既定では未解決のみ。                   |
| `list_pull_request_changes`     | 変更されたファイルの一覧 (追加/編集/削除/名前変更の種別と件数、ベースとヘッドのコミット付き)。   |
| `get_pull_request_diff`         | 実際の統合差分 - ファイル一覧ではなくコードそのもの。指定したパスだけに絞ることもできます。       |
| `get_pull_request_file`         | PRのヘッド (またはベース) コミット時点でのファイル全文。ローカルにないファイルを読むためのものです。 |
| `list_pull_request_commits`     | PRに含まれるコミット。                                                                         |
| `get_pull_request_checks`       | マージ可否: 投稿されたステータスとブランチポリシー評価を統合し、ブロッキングかどうかと、ビルド検証の実行IDを提示。 |
| `list_pipelines`                | プロジェクトのパイプライン一覧 (名前でフィルタリング可能)。                                     |
| `list_pipeline_runs`            | 最近の実行。パイプライン、ブランチ、結果、期間で絞り込めます。                                  |
| `get_pipeline_run`              | 1件の実行 (ステージ/ジョブごとの内訳とエラー件数付き)。                                        |
| `get_pipeline_run_failures`     | 失敗レポート: 失敗したステップ、そのエラー注釈、失敗箇所周辺の抜粋ログ。                        |
| `get_pipeline_step_log`         | 指定した1つのステップまたはジョブのログ - 失敗レポートが何も返さない成功した実行でも取得できます。 |
| `get_pipeline_run_test_results` | テスト結果の内訳と失敗したテストケース。                                                       |
| `get_pipeline_run_changes`      | 前回の実行以降に追加されたコミット - パイプラインが赤くなったときの最初の問いです。               |
| `list_pending_approvals`        | 実行をブロックしている手動承認ゲート (ステージ、手順、承認者、自分が対象かどうか)。              |

書き込みツール (上記のチェックボックスが必要):

| ツール                                     | 動作                                                                                     |
|------------------------------------------|------------------------------------------------------------------------------------------|
| `add_pull_request_comment`         | PRに新しいスレッドを開始、または既存スレッドに返信。Markdown対応。                        |
| `add_pull_request_review_comment`  | ファイルと行に紐づいたコメントを投稿 - 人間のレビュアーのインラインコメントと同じ形で差分上に表示されます。 |
| `set_pull_request_vote`            | レビュー投票を実行 - 承認、提案付き承認、作成者を待機、変更を要求、またはリセット。       |
| `resolve_pull_request_thread`      | コメントスレッドを解決、または再オープン。                                                |
| `run_pipeline`                     | 選択したブランチでパイプライン実行をキュー (テンプレートパラメーター指定可) - YAMLとクラシックの両方、クラウドとオンプレミスの両方に対応。 |
| `cancel_pipeline_run`              | 進行中の実行をキャンセル。                                                                |
| `retry_pipeline_stage`             | 実行中の1ステージだけをその場で再実行 (パイプライン全体を再キューしません)。               |

結果は意図的にコンパクトです。詳しくは下の「切り詰めは必ず報告されます」を参照してください。トリミングはプラグイン自身の
[AIログ分析](AI-Features-ja.md) と同じ仕組みです。

## 決して公開されないもの

設定に関わらず、プルリクエストの完了・破棄や、パイプライン承認ゲートの決定を行うツールは **存在しません** - エージェントは保留中のゲートを
*見る* ことはできても、決して投票はできません。これらの判断はIDE内またはWeb上の人間に委ねられます。作業項目ツールも現時点では含まれていません。

## 切り詰めは必ず報告されます

1回のツール呼び出しがエージェントのコンテキストを埋め尽くさないよう、結果は意図的にコンパクトです: 一覧には上限があり、長いテキストはクリップされ、失敗レポートはエラー周辺の行のみを含みます。何かが切り詰められた場合は必ず結果がそれを伝えます -
`omittedFiles`、`omittedThreads`、`omittedStages`、`truncated` など。エージェントが、実際には一部しか見ていないのに全体を見たと思い込むことはありません。

## トラブルシューティング

- **書き込みツールが「read-only」と返す** - <ui-path>Settings | Tools | DevOps Lens | AI Settings</ui-path> の **Let AI agents change Azure DevOps** をオンにしてください。再起動は不要です。
- **「No Azure DevOps connection」** - まずPull Requestsツールウィンドウを開き、サインインしてリポジトリを選択してください。
- **ツールがまったく表示されない** - IDEのMCP Serverプラグインが無効か、クライアントがIDEのサーバーに接続されていません。<ui-path>Settings | Tools | MCP Server</ui-path> を確認してください。
- **エージェントが別のPRを操作した** - `get_ide_context` または `find_pull_request_for_branch` を使うよう指示してください。「自分のPR」が推測ではなく実際のIDに解決されます。
