## 자격 증명

| 자격 증명        | 저장 위치                                                                                                  |
|------------------|------------------------------------------------------------------------------------------------------------|
| Azure DevOps PAT | IDE의 `PasswordSafe` → 시스템 키체인(macOS Keychain, Windows Credential Manager, GNOME Keyring / KWallet). |
| OAuth 갱신 토큰  | 동일 - `PasswordSafe`. 디스크에 평문으로 저장되는 경우는 없습니다.                                         |
| AI 공급자 API 키 | 동일 - `PasswordSafe`, 공급자 유형(OpenAI, Claude, …)별로 하나의 키 슬롯이 있습니다.                       |

## Azure DevOps로 전송되는 항목

이 플러그인은 Azure DevOps REST API 위에 있는 얇은 클라이언트입니다. 모든 호출은 사용자가 구성한 조직 (`dev.azure.com/<org>` 또는 온프레미스 Azure DevOps Server)
으로 직접 전송됩니다. 어떤 것도 서드파티 서버를 경유하지 않습니다.

호출은 다음과 같은 경우에 이루어집니다.

- PR 도구 창을 열 때 (초기 목록 가져오기).
- 60초 백그라운드 동기화가 실행될 때.
- PR을 열 때 (타임라인 + diff (변경 내용) 가져오기).
- 댓글 게시, 투표, 확인 표시, 완료 또는 중단을 할 때.
- Azure DevOps 원격 저장소에 대한 `git fetch` / `git push` 자격 증명 전달을 생성할 때.
- IDE에 연결한 AI 에이전트가 Azure DevOps MCP 도구를 호출할 때 - 아래를 참조하세요.

## AI 공급자로 전송되는 항목 {id="whats-sent-to-ai-providers"}

AI가 **활성화**되어 있고 공급자가 구성된 경우에만 해당됩니다. 플러그인은 사용자가 트리거한 작업에 대해서만 아웃바운드 호출을 합니다.

> AI 공급자를 추가하거나 편집할 때, 플러그인은 모델 드롭다운을 채우기 위해 해당 공급자의 API 키를 사용하여 인증된 **모델 목록** 요청 (예: `GET /v1/models`)을 한 번 보냅니다. 이것은
> 사용자가 트리거한 작업이 아니라 설정 시점에 실행되는 유일한 AI 요청입니다. PR 코드, diff (변경 내용), 프롬프트는 전송되지 않으며 - 모델 목록 호출만 전송됩니다 - 결과는 약 30분 동안 캐시됩니다.
> 로컬 공급자 (localhost 주소의 Ollama)는 이를 사용자 컴퓨터에 유지합니다.
> {style="note"}

### 기능별 데이터 흐름

| 기능                    | 공급자가 보는 내용                                                             |
|-------------------------|--------------------------------------------------------------------------------|
| **Summarize PR**        | PR 제목 + 설명 + diff(**Max diff size**로 잘림, 기본값 200 KB).                |
| **AI review pass**      | 변경된 각 파일의 전체 파일별 diff. **Max diff size**보다 큰 파일은 건너뜁니다. |
| **Explain code**        | 선택한 파일의 내용(보이는 범위만이 아니라 파일 전체).                          |
| **Commit message**      | 스테이징된 diff(`git diff --cached`가 생성하는 것과 동일).                     |
| **Title & description** | 브랜치 이름 + 커밋 메시지 + diff(위와 같이 잘림).                              |

diff는 IDE를 떠나기 전에 사전 필터링됩니다: 잠금 파일, 압축 (minified)·자동 생성 파일, 바이너리, 빌드 출력 폴더는 제거됩니다. 이름이 변경된 파일은 실제 편집 내용만 포함되고, 삭제된 파일은
내용 대신 한 줄짜리 메모 (경로와 삭제된 줄 수)만 포함됩니다.

각 AI 요청에는 플러그인이 해당 기능에 대해 구성한 시스템 프롬프트도 함께 전달됩니다. 이러한 프롬프트는 <ui-path>Settings | Tools | DevOps Lens | AI
Settings | Configure Prompts</ui-path>에서 재정의할 수 있습니다.

### 공급자 데이터 흐름 매트릭스

| 공급자                 | 요청이 전송되는 위치                                                                                             |
|------------------------|------------------------------------------------------------------------------------------------------------------|
| **Claude (Anthropic)** | `api.anthropic.com`(또는 사용자 지정 기본 URL).                                                                  |
| **OpenAI**             | 기본적으로 `api.openai.com`, 또는 사용자가 구성한 기본 URL(Azure OpenAI, vLLM, 자체 호스팅).                     |
| **Gemini (Google)**    | Google의 AI Studio / Vertex AI 엔드포인트.                                                                       |
| **Ollama**             | 사용자가 설정한 엔드포인트, 일반적으로 `http://localhost:11434`. localhost 주소인 경우 **네트워크 송신 없음**.   |
| **Claude Code CLI**    | `claude` 바이너리가 인증과 라우팅을 처리합니다 - 데이터 흐름은 Anthropic의 CLI 약관에 따라 제어됩니다.           |
| **OpenAI Codex CLI**   | `codex` 바이너리의 인증과 라우팅.                                                                                |
| **GitHub Copilot CLI** | `copilot` 바이너리는 사용자의 Copilot 구독을 사용합니다 - 데이터 흐름은 GitHub Copilot의 약관에 따라 관리됩니다. |

플러그인은 이러한 요청에 헤더, 텔레메트리 또는 분석을 추가하지 않습니다. 업스트림 공급자가 보는 것은 정확히 플러그인이 전송한 것입니다.

## MCP 에이전트가 볼 수 있는 것 {id="what-an-mcp-agent-can-see"}

IDE에 내장된 MCP 서버에 AI 에이전트(Claude Code, Codex CLI, Copilot CLI 등)를 연결하면 플러그인이 Azure DevOps 도구를
제공합니다. 이는 위의 모든 내용과 방향이 반대입니다. *플러그인이* AI 공급자에게 무언가를 보내지는 않습니다. 에이전트가 요청하면 플러그인이
**사용자의** 기존 연결로 **사용자의** Azure DevOps 조직에 질의하고 그 결과를 에이전트에 돌려주며, 그다음은 에이전트 자신의 모델과
약관에 따릅니다.

- **토큰은 절대 공유되지 않습니다.** 도구는 이미 인증된 클라이언트로 IDE 안에서 실행됩니다. 에이전트는 자격 증명이 아니라 결과만 받습니다.
- **새로운 목적지는 없습니다.** 이 호출들은 이 페이지의 다른 요청과 동일한 Azure DevOps 조직으로 갑니다.
- **에이전트가 읽을 수 있는 것**: 연결된 리포지토리에 대한 풀 리퀘스트 세부 정보, 댓글 스레드, 변경된 파일, diff 자체, 병합 검사,
  파이프라인, 실행, 실패 및 단계 로그, 테스트 결과. 에이전트가 읽은 내용은 자신의 모델로 전달될 수 있습니다.
- **허용하기 전에는 할 수 없는 것**: 댓글, 투표, 스레드 해결, 파이프라인 실행 및 취소, 스테이지 재시도는
  <ui-path>Settings | Tools | DevOps Lens | AI Settings</ui-path>에서 **Let AI agents change Azure DevOps**를 체크하기 전까지 꺼져 있습니다.
- **절대 할 수 없는 것**: 풀 리퀘스트 완료 또는 폐기, 파이프라인 승인 게이트 결정.

IDE의 MCP 서버에 에이전트를 연결하지 않았다면 이 내용은 해당되지 않습니다. [](MCP-Tools-ko.md)을 참조하세요.

## AI 응답 캐싱 {id="caching-ai-responses"}

기능이 결과를 반환하면, 플러그인은 다음을 키로 하여 결과를 캐시합니다.

- PR ID.
- 요청 시점의 diff SHA.
- 단조 증가하는 `cacheGeneration` 카운터 - 프롬프트를 편집하거나, 공급자를 변경하거나, 요약 카드의 톱니바퀴 팝업에서 **Clear cached AI responses**를 클릭할 때 증가합니다.

캐시 적중 시 아웃바운드 호출 없이 즉시 반환됩니다. 캐시된 응답은 IDE 로컬 상태에 저장되며 플러그인 제거 시 삭제됩니다.

## 텔레메트리

플러그인은 **사용 분석을 전혀 수집하지 않습니다**. 어떤 기능을 사용하는지, 풀 리퀘스트를 얼마나 자주 여는지, 무엇을 클릭하는지 추적하는 것은 아무것도 없습니다. "phone home" 핑도 없으며, 위에
나열된 Azure DevOps 및 AI 공급자 요청 외에 백그라운드에서 사용자 컴퓨터를 떠나는 호출은 없습니다.

유일한 예외는 크래시 보고서이지만, 이는 플러그인이 아니라 IDE 자체 기능입니다. 아래를 참조하세요.

## 크래시 보고서 {id="crash-reports"}

### 이 기능이 존재하는 이유 {id="why-this-exists"}

플러그인에 버그가 발생하면 정작 쓸모 있는 증거인 스택 트레이스는 로그 파일에 남습니다. 그것을 이슈에 붙여 넣으려면 파일을 직접 찾아 열고, 읽고, 민감한 정보를 지워야 합니다. 실제로 그렇게 하는 사람은 거의
없기 때문에 대부분의 신고는 "가끔 diff (변경 내용)가 비어 있어요" 같은 형태로 도착하고, 그런 신고는 대개 고칠 수 없습니다.

크래시 보고서는 이 과정을 클릭 한 번으로 줄여 실제 수정이 가능하게 만듭니다. 이것은 추적 채널이 아니라 진단 채널입니다. 플러그인이 실제로 예기치 못한 오류를 던졌을 때 **만** 동작합니다.

### 누가 전송하나요 {id="who-sends-it"}

**플러그인이 아니라 사용자의 IDE입니다.** DevOps Lens의 크래시 보고는 JetBrains IDE 자체 기능입니다. IDE가 보고서를 구성해 JetBrains Marketplace로
보내고, Marketplace가 이를 플러그인 개발자에게 전달합니다. 플러그인은 이 서비스에 등록만 되어 있을 뿐 코드를 제공하지 않으며, 보고서에 무언가를 추가하거나 걸러내거나 전송을 막을 수 없습니다.

### 언제 발생하나요 {id="when-it-fires"}

플러그인이 처리되지 않은 예외를 던지면 IDE가 표준 오류 대화 상자(상태 표시줄의 빨간 아이콘)를 표시할 수 있습니다. 안정 버전은 EAP 버전보다 플러그인 오류에 대해 더 조용합니다. 그 대화 상자에는 **Report to the Third-Party Plugin**
버튼과, 누를 경우 무엇이 일어나는지 설명하는 JetBrains의 고지가 함께 표시됩니다. 대화 상자를 닫으면 아무것도 전송되지 않습니다.

한 가지 예외가 있습니다. IDE의 **자동 예외 보고**(직접 켜지 않는 한 꺼져 있는 JetBrains 데이터 공유 설정)를 켜 두었다면, IDE가 대화 상자를 먼저 표시하지 않고 스스로 보고서를 보낼 수
있습니다.

예상 가능한 실패는 이 경로에 도달하지 않습니다. 오프라인 상태, 만료된 토큰, 403, 없는 파일은 모두 처리되어 로컬에만 기록됩니다. 버그가 아니므로 크래시 보고서를 만들지 않습니다.

### 전송되는 항목 {id="what-is-sent"}

| 포함되는 항목      | 세부 내용                                                                                                                                  |
|--------------------|--------------------------------------------------------------------------------------------------------------------------------------------|
| 스택 트레이스      | 클래스 이름, 메서드 이름, 파일 이름, 줄 번호 - 실패한 코드 경로. 있는 그대로 전송됩니다                                                    |
| 오류 메시지        | 실패한 코드가 생성한 텍스트. 있는 그대로 전송됩니다                                                                                        |
| 사용자의 설명      | 대화 상자의 의견란에 입력한 경우 그 문장만                                                                                                 |
| 플러그인 버전      | 예: `1.4.2`                                                                                                                                |
| IDE 이름과 빌드    | 예: `IntelliJ IDEA 2026.2 (Ultimate Edition), build IU-262.9437.185`                                                                       |
| 운영 체제          | 이름, 버전, 아키텍처, CPU 수                                                                                                               |
| Java 런타임        | IDE의 부트 JVM 빌드와 공급업체. 예: `21.0.5+8-b631.28 (JetBrains s.r.o.)` - 일부 렌더링/아이콘 결함은 IDE 버전만으로는 알 수 없는 JetBrains Runtime 버그입니다 |
| 마지막 IDE 액션    | 오류 직전에 실행한 액션의 식별자                                                                                                           |
| 설치된 플러그인    | 번들되지 않은 플러그인의 식별자                                                                                                            |
| 설치 식별자        | IDE가 오류 보고용으로 생성하는 고정 식별자. 이름이나 이메일 주소는 포함하지 않습니다                                                       |

### 걸러지지 않는 항목 {id="what-is-never-sent"}

보고서는 IDE의 것이므로 플러그인이 마스킹할 수 없습니다. 실제로는 다음을 의미합니다.

- **사용자의 코드는 들어 있지 않습니다.** 파일 내용, diff, 댓글 본문, 풀 리퀘스트 제목이나 설명은 포함되지 않습니다. 플러그인이 애초에 그런 값을 예외에 담지 않기 때문입니다.
- **플러그인은 자격 증명을 오류 메시지에 넣지 않습니다.** 개인용 액세스 토큰(PAT), OAuth 토큰, AI API 키는 IDE의 비밀번호 저장소에 보관되며 스택 트레이스가 닿을 수 있는 곳에
  없습니다.
- **업무를 식별할 수 있는 이름은 나타날 수 있습니다.** 오류 메시지가 조직, 프로젝트, 리포지터리, 서버 호스트 이름을 담을 수 있고, 입출력 오류에서는 파일 경로가 나타날 수 있습니다. 전송 과정에서
  이를 제거하는 단계는 없습니다.
- **의견란에 입력한 내용은 그대로 전송됩니다.** 코드, 자격 증명, 티켓 내용, 기밀 이름을 붙여 넣지 마세요.

직접 읽어 본 뒤에 보내고 싶다면 대화 상자 대신 아래의 진단 스냅샷을 사용하세요. 공식적인 법적 설명은 [영문 개인정보 처리방침](%docs_url%privacy-policy.html#crash-reports)에
있습니다.

### 먼저 직접 읽어 볼 수 있는 스냅샷 {id="anonymization-happens-on-your-machine"}

<ui-path>Help | Copy DevOps Lens Diagnostics</ui-path>는 플러그인이 여전히 직접 구성하는 유일한 보고서이며, 사용자나 사용자의 업무를 식별할 수 없는 값으로만
이루어져 있습니다.

- 플러그인, IDE, 운영 체제, Java 버전
- 구성된 계정의 **개수**와 그것이 `cloud`, `on-prem` 또는 둘 다인지 여부 - 서버 주소는 포함되지 않습니다
- 플러그인이 현재 온라인이라고 판단하는지 여부
- 캐시 카운터(항목 수, 적중률). 캐시에 담긴 내용은 포함되지 않습니다

결과는 클립보드에만 놓이므로 누구보다 먼저 사용자가 내용을 확인하고 어디에 붙여 넣을지 정합니다. 뒤에서 마스킹이 이루어지지는 않지만 필요하지도 않습니다. 조직·프로젝트·리포지터리·서버·사용자 이름에
해당하는 값은 애초에 수집하지 않기 때문입니다.

### 어디로 전송되나요 {id="where-it-goes"}

보고서는 **JetBrains Marketplace**로 전송되며, Marketplace는 이를 이 플러그인의 Exception Analyzer 페이지로 전달합니다. 이 페이지는 플러그인 개발자가 봅니다.
공개 이슈 트래커에 게시되지 **않으며** 외부에 공개되지도 않습니다.

이 서비스를 운영하고 보고서를 먼저 받는 곳은 JetBrains s.r.o.입니다. 어떤 용도로 사용될 수 있는지는
[JetBrains Exception Analyzer 계약](https://www.jetbrains.com/legal/agreements/exception_analyzer.html)에 정해져 있으며, IDE가 대화 상자 아래
고지에서 이 문서를 링크합니다. 개발자는 Marketplace 화면을 통해 보고서를 읽습니다.

플러그인 개발자가 운영하는 서버는 여기에도, 다른 어디에도 없습니다. 풀 리퀘스트, 코드, 자격 증명, AI는 모두 사용자의 IDE와 사용자의 Azure DevOps 조직 또는 자신의 AI 공급자 사이에서
직접 오갑니다. 공식적인 법적 설명은 [영문 개인정보 처리방침](%docs_url%privacy-policy.html#crash-reports)에 있습니다.

### 아무것도 보내고 싶지 않다면 {id="if-you-would-rather-not-send-anything"}

오류 대화 상자를 닫으면 아무것도 컴퓨터를 떠나지 않습니다. IDE의 **자동 예외 보고**를 켜 두었다면 그것도 꺼 주세요. 묻지 않고 보고서를 보낼 수 있는 설정이 바로 그것입니다.

그래도 버그가 고쳐지길 원한다면 <ui-path>Help</ui-path> 메뉴의 <b>Copy DevOps Lens Diagnostics</b>를 사용해 내용을 직접 확인한 뒤
[공개 이슈](%new_bug_url%)에 붙여 넣으세요. [문제 신고하기](Troubleshooting-ko.md#reporting-a-problem)를 참조하세요.

팀 전체에 대해 이 경로를 닫고 싶은 관리자는 IDE 배포 설정에서 IDE의 오류 보고 대화 상자를 비활성화할 수 있습니다. 대화 상자가 없으면 누를 버튼도 없습니다.

## 모든 것을 로컬에 유지하기

데이터 레지던시 요구 사항이 있는 조직의 경우:

1. **온프레미스 Azure DevOps Server**(이전 TFS)를 사용하세요. PR, 댓글, API가 모두 자체 서버에 존재합니다.
2. 마스터 스위치로 **AI를 비활성화**하거나, `localhost`에서 실행되는 **Ollama 인스턴스로 모든 AI 기능을 라우팅**하세요. 오프라인 지원 모델 (Llama, Mistral 등)과 함께
   사용하면 어떤 데이터도 사용자 컴퓨터를 떠나지 않습니다.
3. 서드파티 CLI의 약관을 상속받고 싶지 않다면 **CLI AI 공급자를 피하세요** - 편리하지만 플러그인 입장에서 데이터 흐름이 불투명합니다.

## 사용자 지정 AI 공급자 (엔터프라이즈) {id="custom-ai-providers-enterprise"}

%product%는 확장 지점을 노출하여 엔터프라이즈의 내부 플러그인이 기본 제공 AI 구현을 대체하고 예를 들어 내부 게이트웨이를 통해 AI 호출을 라우팅할 수 있도록 합니다. 확장 지점은 `plugin.xml`의
`intellij.vcs.azuredevops` 네임스페이스 아래에 선언되어 있습니다 - 구현 세부 정보는 플러그인의 GitHub 리포지토리를 참조하세요.

우선순위가 더 높은 확장이 등록되면, 해당 기능에 대해 플러그인의 기본 제공 기본값은 우회됩니다.
