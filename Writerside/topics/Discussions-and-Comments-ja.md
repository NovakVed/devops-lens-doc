# ディスカッションとコメント

<tldr>
    <p><b>場所</b>: どのスレッドにもある返信ボックス - 差分内のインライン、タイムライン、エディターのオーバーレイのいずれか。</p>
    <p><b>未解決スレッドをたどる</b>: <shortcut>F8</shortcut> / <shortcut>⇧F8</shortcut>、および<a anchor="review-bar">レビューバー</a>のフィルターチップ。</p>
</tldr>

IDE を離れることなく、プルリクエストで本格的な会話ができます。markdown エディター、@メンション、作業項目やプルリクエストへの参照、変更の提案、画像の添付、AI
による文法調整、スレッドの解決に対応しています。

## スレッドが表示される場所

同じスレッドが 3 か所に表示されます。

- **差分内のインライン** - 参照している行にアンカーされます。[](Code-Review-ja.md)を参照してください。
- **タイムライン** - すべてのスレッドとプルリクエストのイベントを時系列で表示します。プルリクエストの詳細ビューにある
  **View Timeline** リンクから開きます。 (**Find in timeline** で検索できます。)
- **エディター内** -
  プルリクエストのブランチがチェックアウトされているときに、通常のエディターに重ねて表示されます。[エディターでのレビュー](Review-in-Editor-ja.md)
  を参照してください。

## コメントエディター

タイムライン、差分インレイ、インライン編集、そして Create-PR の説明欄まで、すべてのコメントエディターは同じコンポーザーです。左上に
**Write | Preview** のタブストリップがあり、書式設定ツールバーが同じ上部ストリップに並び（右端に **Polish grammar &amp;
spelling with AI**）、下段には **Markdown is supported** と **Add files** が送信ボタンの左側に並びます。

![Write | Preview タブと上部の書式設定ツールバーストリップ、送信ボタンの隣の下段にある Add files リンクを備えたコメントコンポーザー](comment-editor-ja.png){ width="640" border-effect="line" }

| グループ       | ボタン                                                                      |
|----------------|-----------------------------------------------------------------------------|
| **References** | Mention user (`@`)、Reference work item (`#`)、Reference pull request (`!`) |
| **Formatting** | Heading、Bold、Italic、Inline code、Link                                    |
| **Lists**      | Bulleted、Numbered、Task list                                               |
| **AI**         | **Polish grammar &amp; spelling with AI**                                   |

差分／エディターのインレイでは **Insert code suggestion** も使えます。キーボード: <shortcut>⌘B</shortcut> 太字、<shortcut>
⌘I</shortcut> 斜体、<shortcut>⌘E</shortcut> インラインコード、<shortcut>⌘K</shortcut> リンク、<shortcut>⌘↵</shortcut> 送信
(または <shortcut>Ctrl</shortcut> 相当のキー)。

**Preview** をクリックすると、エディターが markdown
のレンダリングビューに切り替わります。これは投稿済みのコメントで使われるレンダリングと同じなので、プレビューした内容が投稿される内容と一致します。Preview
を表示している間は書式設定ツールバーが隠れます。 **Write** をクリックすると編集に戻ります。空の下書きは *Nothing to
preview* としてプレビューされます。

下段の **Markdown is supported** はリンクです。クリックすると Microsoft の Azure DevOps markdown
ガイダンスがブラウザーで開きます。ここで実際にレンダリングされるもの - タスクリスト、絵文字、サイズ指定した画像、ハイライトされたコードフェンス、そして Azure DevOps
が wiki 専用としているもの - については [](Markdown-ja.md) を参照してください。

> **Polish grammar &amp; spelling with AI** は、下書き (または選択範囲) をその場で 1
> 回の取り消し可能な編集として書き換えます。[AI プロバイダーの設定](AI-Features-ja.md)が必要です。AI がオフのときは、このボタンは表示されません。
> {style="tip"}

## @メンション

**Mention user** をクリックするか `@` を入力すると、組織内のメンバーのオートコンプリートが開きます。矢印キーと <shortcut>
Enter</shortcut> で 1 人を選びます。メンションされたユーザーには Azure DevOps の通知が届きます。

既存の `@mention` をクリックすると、そのユーザーのアバターと名前を表示する小さな **author card** が開きます。メールアドレスが分かっている場合
(プルリクエストの作成者またはレビュアー) は、このカードで **Copy email** と **Send email** が利用できます。

> @メンションのオートコンプリートには **Identity (Read)** が必要です。PAT の作成時にはこれを選択してください。Microsoft サインインではアプリ必須セットの一部として自動的に要求されます。[](Permissions-ja.md) を参照してください。
> {style="note"}

## 作業項目への参照 {id="work-items"}

**Reference work item** をクリックするか `#` を入力すると、作業項目のオートコンプリートが開きます。直近で操作した 50
件、または種類・ID・タイトルに一致する最大 5 個のキーワードによる検索結果が表示されます。1 つ選ぶと `#<id>` (たとえば
`#1234`) が挿入されます。

投稿された `#1234` は、 **ブラウザーの Azure Boards** でその作業項目を開くリンクとしてレンダリングされます。IDE
内に作業項目のビューはないため、`@mention` とは違ってカードは開かず、`!567` のプルリクエスト参照とは違って IDE
内で開くこともありません。1 つだけ衝突に注意してください。行頭では、`#` に続く数字は見出しではなく参照になります。
[](Markdown-ja.md#hash)を参照してください。

> 参照は関連付けではありません。Azure Boards
> が追跡し、作業項目自体に表示されるリンクを作るのは、[サイドバー](#the-timeline-sidebar)の **Work items** 行 (**+**
> でリンク、右クリックでリンク解除) です。コメントや説明に `#1234` と入力しても、クリックできる参照が得られるだけです。
> {style="note"}

## 画像と添付ファイル {id="images-and-attachments"}

画像を添付する方法は 3 つあります。

- **Add files** - 下段 (送信ボタンの左側) の **Add files** リンクをクリックして、ディスクから画像ファイルを選びます。
- クリップボードから画像を **貼り付け** ます (<shortcut>⌘V</shortcut> / <shortcut>Ctrl+V</shortcut>)。
- 画像ファイルをエディターに **ドラッグ &amp; ドロップ** します。

サポートされる形式は `png`、`jpg`、`jpeg`、`gif`、`webp`、`bmp`、`svg` です。アップロードごとに *Uploading…*
プレースホルダーが表示され、その後インラインの markdown 画像になります。投稿済みの画像を右クリックすると **Copy Image
Link** または **Download Image…** が利用できます。

投稿済みの画像を **クリック**すると、 **Fit to Window**、 **Actual Size**、 **Zoom In**、 **Zoom Out**、 **Save Image…**、
**Copy Image**、 **Open in Browser** を備えたズーム可能なビューアーで開きます。ビュー内キーは <shortcut>F</shortcut>
でウィンドウに合わせる、<shortcut>1</shortcut> で実寸表示、<shortcut>+</shortcut> / <shortcut>-</shortcut> でズームです。

> コメント内のフェンス付きコードブロックは、 **IDE 本来のシンタックスハイライト**で描画されます。フェンスに言語（
> ` ```kotlin `、` ```csharp `、` ```dockerfile ` など）を付けると、そのファイルタイプがエディターで色分けされるのと同じようにブロックが色付けされます。
> {style="tip"}

## 変更の提案 {id="suggested-edits"}

変更を説明する代わりに具体的な変更を提案するには、 **suggestion** を使います。差分／エディターのインレイで **Insert code
suggestion** をクリックする (コメント対象の行があらかじめ入力されます) か、```` ```suggestion ```` ブロックを入力します。

![Apply Locally アクションを備えた変更の提案](suggested-edit.png){ width="560" border-effect="line" }

スレッドには **Suggested change** カードが表示され、 **Apply Locally** (および 1 ステップで適用してコミットする
**Commit…**) が使えます。Apply は、プルリクエストのブランチがチェックアウトされるまで、また解決済みのスレッドでは無効になっています。

![スレッド上の Suggested change カード。Apply Locally と Commit… が並ぶ](suggestion-block-ja.png){ width="640" border-effect="line" }

## 返信、解決、スレッドの管理

- **Reply** - フォローアップを追加します。Azure DevOps のスレッドはフラットなので、返信はスレッドの末尾に追加されます。
- **Resolve / Reopen** - 完了したスレッドを閉じたり、再度開いたりします。解決済みのスレッドは目立たなくなり、差分フィルターが
  *Show only unresolved* に設定されているときは非表示になります。
- **👍 Thumbs up** - コメント本文の下にあるリアクション行の「いいね」ボタンです (レビュースレッドでは **Reply** /
  **Resolve** と共有されます)。「いいね」が 1 件以上つくとカウントが表示され、自分が「いいね」するとゴールドになります。ツールチップは
  **Thumbs up** と **Remove thumbs up** の間で切り替わります。
- **More actions (⋯)** - コメントヘッダーのオーバーフローメニューです。どのコメントでも **Copy link**、 **Copy Markdown**、
  **Quote reply** (コメントを `>` ブロック引用としてこのスレッドの返信エディターに挿入します) が使えます。自分のコメントではさらに
  **Edit** と **Delete** が使えます。メニューが開いている間、各アクションは 1 文字のキーで実行できます: <shortcut>
  L</shortcut> Copy link、<shortcut>M</shortcut> Copy Markdown、<shortcut>Q</shortcut> Quote reply、<shortcut>E</shortcut>
  Edit、<shortcut>D</shortcut> Delete。

![返信コンポーザーを開いたインラインスレッド](reply-to-thread-ja.png){ width="720" border-effect="line" thumbnail="true" }

### スレッドのステータス

解決済み／未解決に加えて、スレッドはステータスチップを持ちます。これ (**Change status**) をクリックすると、次の間で切り替えられます。

| ステータス    | 意味                                               |
|---------------|----------------------------------------------------|
| **Active**    | 新しいスレッド (チップは表示されません)。          |
| **Pending**   | 作成者による変更を待っています。                   |
| **Resolved**  | 変更が適用されました。                             |
| **Won't fix** | 認識されていますが、変更は行われません。           |
| **Closed**    | ディスカッションは完了し、アクションはありません。 |

### スレッドのコンテキスト

スレッドは、コメント対象行の周囲に数行のコードを表示します。表示する行数は、[](Settings-ja.md)の **Lines shown
above a comment** と **Lines shown below a comment** で設定できます。既定は上下ともに 3 です。

## 長い会話をたどる {id="review-bar"}

会話の上には **レビューバー** - タイムラインのコントロールストリップ - があります。左側はディスカッションの件数
(`N conversations · M unresolved`) を数え、右側にはフィルターチップが並びます。

| チップ                | 動作                                                                                                                                                                                    |
|-----------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **All events**        | タイムラインを 1 種類のイベント - コメント、コミットと更新、投票、状態の変更、レビュアー、システムイベント - に絞り込むドロップダウンです。既定は *All events* で、すべてを表示します。 |
| **Mine**              | 自分が参加しているスレッドのみを表示します。                                                                                                                                            |
| **Needs my reply**    | 自分にボールがあるオープンなスレッドを表示します。                                                                                                                                      |
| **Participants**      | スレッドを開始した人で絞り込みます。ライブに反映される複数選択のピープルピッカーです。選択するとチップのラベルが *Participants: &lt;name&gt; +N* に変わります。                         |
| **Collapse resolved** | 解決済みのスレッドをそれぞれ 1 行に折りたたみます。セッションをまたいで記憶され、<shortcut>H</shortcut> で切り替わるのと同じものです。                                                  |
| **?**                 | キーボードのチートシートです。                                                                                                                                                          |

残りを片付けるのに役立つアフォーダンスがもう 2 つあります。

- タイムラインの上に **未解決ナビゲーター** がフローティング表示されます。シェブロンと `N of M` のカウンターがあり、すべて片付くと
  *No unresolved* と表示されます。<shortcut>F8</shortcut> / <shortcut>⇧F8</shortcut> のマウス版です。
- スクロールバーのレーンには、IDE 自身のエラーストライプと同じように、 **未解決スレッドごとのティック**
  が表示されます。ティックをクリックすると、そのスレッドに直接ジャンプします。

## タイムラインのサイドバー {id="the-timeline-sidebar"}

右サイドバーはプルリクエストのメタデータが集まる場所です。Create フォームとは違い、プルリクエストの全期間を通じて編集できます。

| セクション        | できること                                                                                                                                                                                                                                                                                                                                                        |
|-------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Reviewers**     | **Required** と **Optional** のサブグループがあり、それぞれに追加用の **+** があります。行のオーバーフローメニューには **Make optional** / **Make required** と **Remove** があります。ブランチポリシーによって追加されたレビュアーにはポリシーアイコンと *Reviewers were added by policy* のツールチップが付きます。空のグループは *No reviews* と表示されます。 |
| **Tags**          | **+** でタグを追加し、タグを右クリックすると削除できます。                                                                                                                                                                                                                                                                                                        |
| **Work items**    | **+** で作業項目をリンクします。                                                                                                                                                                                                                                                                                                                                  |
| **AI review**     | 直近の AI レビューがまだ最新かどうか。[](AI-Features-ja.md)を参照してください。                                                                                                                                                                                                                                                                            |
| **Notifications** | **Mute live updates** / **Resume live updates**。[プルリクエスト](Pull-Requests-ja.md#refresh-and-background-sync)を参照してください。                                                                                                                                                                                                                            |
| **Participants**  | プルリクエストに対して何らかの操作をしたすべての人 - 作成者、投票したレビュアー、コメントの投稿者、コメントに「いいね」した人 - を重複排除し、作成者を先頭にして表示します。                                                                                                                                                                                      |

> レビュアーとして追加されたチームの投票は **Approved via &lt;member&gt;** と表示され、チームを代表して実際に投票した人物を示します。
> {style="note"}

## タイムラインイベント

タイムラインは、コメントに加えて、プルリクエストに起きたことを記録します。投票の変更、レビュアーの追加／削除、作業項目のリンク／リンク解除、完了したステータスチェック、ドラフトと
ready の切り替え、そして完了または取り消しです。

見た目以上のことをしている 2 種類のイベントは、特に取り上げておく価値があります。

- **コミットの追加。** プッシュのたびに *N commits added* イベントが追加され、新しいコミットがクリック可能な短縮 SHA
  で一覧表示されます。
- **更新 (イテレーション)。** 更新はすべて *updated &lt;branch&gt; from &lt;sha&gt; to &lt;sha&gt;* として描画され、
  **Compare changes** リンクが付きます。クリックすると変更ツリーがその更新分だけに再スコープされます。⋮ メニューの
  **Review Changes Since…** が提供するのと同じイテレーションレビューに、1
  クリックで到達できます。[コードレビュー](Code-Review-ja.md#compare)を参照してください。source
  の先端が実際に動いていない場合、このリンクは省かれます。

### グループ化されたレビュー

誰かが一度にいくつものコメントを残した場合、タイムラインはそれらを **1 つのレビューイベント**にまとめます。5
件のエントリがページに散らばる代わりに、その人の投票を示すヘッダー、任意のサマリー、折りたためるファイルごとの行が表示されます。

![タイムライン上のグループ化されたレビュー: 1 つのヘッダーとファイルごとの折りたたみ行](grouped-review-ja.png){ width="720" border-effect="line" thumbnail="true" }

プラグインから送信されたレビューは正確にグループ化されます。他の場所 (たとえば Azure DevOps の Web UI)
で残されたまとまりは、同じ作成者のコメントが数分以内に連続して投稿された場合にグループ化され、近い時刻の投票がヘッダーに畳み込まれます。

### 古くなったコメント

後続のコミットがコメントの対象行を変更すると、そのスレッドに **Outdated** チップが付きます。このチップはトグルでもあります。クリックすると
*元の差分 - このコメントが書かれた時点のコード*が表示され、もう一度クリックすると現在のコードに戻ります。スニペットを再構成できない場合、スレッドには
*Diff preview isn't available for this comment* と表示されます。
