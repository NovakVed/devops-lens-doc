# Markdown

<tldr>
    <p><b>対象</b>: すべてのコンポーザー - コメント、返信、プルリクエストの説明、Create-PR フォーム。</p>
    <p><b>構文リファレンス</b>: コンポーザー下段の <b>Markdown is supported</b> リンクから、Microsoft の Azure DevOps
       markdown ガイダンスを開けます。</p>
</tldr>

プラグインで書く内容はすべて **Azure DevOps 方言の markdown** であり、読む内容はすべてプラグイン自身がレンダリングします。投稿済みのコメント、スレッドの返信、
**Preview** タブ、プルリクエストの説明のいずれも同じパイプラインを通るため、プレビューした内容がそのまま投稿されます。

## すべてのコンポーザーにある構文リンク

コンポーザーの下段には、 **Add files** の左に控えめな **Markdown is supported** リンクがあります。

<deflist>
    <def title="GitHub ではなく Microsoft のガイダンスを開きます">
        クリックすると
        <a href="https://learn.microsoft.com/en-us/azure/devops/project/wiki/markdown-guidance?view=azure-devops">Syntax
        guidance for basic Markdown usage</a> がブラウザーで開きます。これは、いま入力している内容に実際に当てはまるリファレンスです。2
        つの方言は重要な点で異なります。Azure DevOps には独自の画像サイズ拡張、独自の絵文字セット、そして wiki
        専用として残されている構文があります (<a anchor="wiki-only">後述</a>)。
    </def>
    <def title="Write と Preview の両方で表示されます">
        これはモードではなくフィールドについての説明であり、レンダリング結果を確認する Preview こそ構文リファレンスが役に立つ場所です。
    </def>
    <def title="幅を最初に譲ります">
        コンポーザーの下段はレスポンシブです。狭い場所 - 左右分割された差分の片側、幅を詰めたツールウィンドウ - では、まずこのリンクがアイコンだけになり、次に完全に消えます。
        <b>Add files</b> がラベルを手放すより先です。送信ボタンは決して縮まないので、どの幅でも <b>Comment</b> / <b>Reply</b>
        はクリックできます。リンクが消えても失われるものはありません。ドキュメントへのショートカットにすぎず、同じページはブラウザーから 1 クリックで開けます。
    </def>
</deflist>

## レンダリングされる記法

| 記法                  | 入力例                                              | メモ                                                                                     |
|-----------------------|-----------------------------------------------------|-------------------------------------------------------------------------------------------|
| **見出し**            | `# H1` … `###### H6`                                | `#` の後のスペースは省略できます - `#Heading` も動作します。[下記の注記](#hash)を参照。   |
| **強調**              | `**bold**`、`_italic_`、`~~strikethrough~~`         | 打ち消し線の中の強調も保持されます。                                                       |
| **リスト**            | `-` / `*` / `1.`、インデントで入れ子                |                                                                                             |
| **タスクリスト**      | `- [ ] open`、`- [x] done`                          | ☐ / ☑ のグリフで表示されます。状態を示すもので、クリックできるチェックボックスではありません。 |
| **テーブル**          | パイプ区切りのセルと `---` の区切り行               | 実際のセル罫線付きで描画されます。                                                          |
| **リンク**            | `[text](url)`、URL のみ、`[text](#anchor)`          | 開かれるのは `http`、`https`、`mailto` のみです。他のスキームは起動されず無視されます。     |
| **画像**              | `![alt](url)`、`![alt](url =500x250)`               | Azure の `=WxH` 接尾辞も受け付けます。いずれの場合も画像は列幅に合わせて拡縮されます。      |
| **コード**            | `` `inline` `` と ``` ``` ``` のフェンス            | フェンスは IDE のシンタックスハイライトで表示されます - [後述](#code-blocks)。             |
| **引用**              | `> quoted`                                          | **Quote reply** が挿入するのはこの形式です。                                                |
| **水平線**            | `---`                                               |                                                                                             |
| **絵文字**            | `:tada:`、`:+1:`、`:rocket:`                        | 約 270 個の一般的なショートコード。未知のものはそのまま残り、`\:tada:` でエスケープできます。 |
| **エスケープ**        | `\*not italic\*`                                    |                                                                                             |

> `$a^2 + b^2$` のような数式は、組版されず **コードスパン** として表示されます。Azure DevOps
> はブラウザーの数式エンジンでレンダリングしますが、IDE の表示ペインには相当するものがありません。そのため、地の文に紛れて消えるのではなく、ソースのまま表示されます。
> {style="note"}

## 人と作業項目への参照

次の 3 つの参照形式は Azure DevOps 独自のもので、いずれも入力しながら補完されます。

| 種類 | 挿入するもの         | 表示                                                           |
|------|----------------------|----------------------------------------------------------------|
| `@`  | `@<user>`            | 表示名。クリックすると作成者カードが開きます。                 |
| `#`  | `#1234`              | その作業項目へのリンク。ブラウザーの Azure Boards で開きます。 |
| `!`  | `!567`               | その PR へのリンク。IDE 内で開きます。                         |

その背後のピッカーについては [](Discussions-and-Comments-ja.md#work-items) を参照してください。

### `#1234` による作業項目参照 {id="hash"}

`#` に続けて作業項目 ID を書いたものが
[Azure DevOps の作業項目参照](https://learn.microsoft.com/en-us/azure/devops/boards/backlogs/add-link?view=azure-devops)
です。`#` のピッカーが挿入するのと同じトークンであり、Azure DevOps の Web UI
がプルリクエストの説明で解釈するのと同じものです。コメントや説明に `Fixes #1234` と書くと、`#1234` は Azure Boards
でその作業項目を開くリンクとしてレンダリングされます。

> **行頭の `#1234` は見出しではなく参照です。** `#` に続く数字は、行頭であっても作業項目参照として読まれます。そのため
> `#404 Not found` は作業項目 404 へのリンクになります。数字で始まるテキストの見出しを書きたい場合は、
> スペースを入れた標準の形 `# 404 Not found` を使ってください。英字で始まるスペースなしの見出し (`#Overview`)
> には影響しません。
> {style="note"}

この参照が **行わない** ことが 2 つあり、どちらも知っておく価値があります。

- **参照をレンダリングすることは、作業項目をリンクすることと同じではありません。** Azure Boards
  が追跡する関連付けを作るのは、PR サイドバーの **Work items** 行 (および Create フォームの **Work items** フィールド)
  でのリンクです。説明に `#1234` と入力するとクリックできる参照は得られますが、IDE からその行が埋まることはありません。
- **コミットメッセージはサーバーの担当です。** Azure DevOps は、`#1234` を含むメッセージのコミットを *プッシュ*
  したときに作業項目リンクを作成します - [](Git-Integration-ja.md#commit-refs) を参照してください。
  プラグインはこうした参照を追加も書き換えもしません。

## コードブロック {id="code-blocks"}

フェンスに言語を指定すると、そのブロックは **IDE 自身のシンタックスハイライト** でレンダリングされます。エディターでそのファイルタイプに使われるのと同じ配色です。

````
```kotlin
fun greet(name: String) = "Hello, $name"
```
````

レンダリングされたブロックはネイティブの IDE コードブロックの外観を持ち、右上に小さなバッジが付きます。通常は言語名、ポインターがブロックのどこかに重なっている間は
**Copy code** ボタンです。コンポーザーでは、Preview に切り替える前から **入力中に** フェンスがハイライトされます。

役割を持ったコードブロックもあります。 ```` ```suggestion ```` ブロックは、作成者がワンクリックで適用できる **Suggested
change** カードとしてレンダリングされます。 [変更の提案](Discussions-and-Comments-ja.md#suggested-edits) を参照してください。

## 入力中の補完

コンポーザーは 5 種類をインラインで補完します。スペースの後にトリガー文字を入力し、絞り込んでから矢印キーと <shortcut>Enter</shortcut> で選びます。

| トリガー      | 補完対象                                                                                               |
|---------------|--------------------------------------------------------------------------------------------------------|
| `@`           | 組織内の人。                                                                                            |
| `#`           | 作業項目。`#<id>` が挿入され、[Boards へのリンク](#hash)としてレンダリングされます。                   |
| `!`           | プルリクエスト。                                                                                        |
| `:`           | 絵文字ショートコード。Azure DevOps が保存する形式であるショートコード (`:tada:`) が挿入されます。       |
| ```` ``` ```` | コードフェンスの言語。IDE に実際に存在するファイルタイプから、各行にアイコン付きで表示されます。        |

> `:` 単体や `10:30` のような時刻で絵文字リストが開くことはありません。また ``` 単体 (通常は *閉じ* フェンス) で言語リストが開くこともありません。
> {style="tip"}

## Azure DevOps が wiki 専用としている記法 {id="wiki-only"}

Microsoft のガイダンスは wiki、プルリクエストのコメント、その他の場所を 1
ページで扱い、どの構文がどこで使えるかを示しています。次のものは **wiki 専用** です。Azure DevOps
自身がプルリクエストのコメントではレンダリングしないため、プラグインでもレンダリングされません。

- `[[_TOC_]]` の目次
- Mermaid ダイアグラム
- `:::` の折りたたみセクション
- 埋め込み動画
- Azure Boards のクエリ結果
- 生の HTML タグ
