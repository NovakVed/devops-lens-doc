## 資格情報

| 資格情報                   | 保存場所                                                                                                              |
|----------------------------|-----------------------------------------------------------------------------------------------------------------------|
| Azure DevOps PAT           | IDE の `PasswordSafe` → システムキーチェーン（macOS Keychain、Windows Credential Manager、GNOME Keyring / KWallet）。 |
| OAuth リフレッシュトークン | 同上 - `PasswordSafe`。ディスク上での平文保存は一切行われません。                                                     |
| AI プロバイダー API キー   | 同上 - `PasswordSafe`。プロバイダータイプ（OpenAI、Claude、…）ごとに 1 つのキースロットです。                         |

OS ごとのキーチェーンの詳細、および PAT のローテーションや失効の方法については、[](Authentication-ja.md)を参照してください。

## Azure DevOps に送信される内容

このプラグインは Azure DevOps REST API 上の薄いクライアントです。すべての呼び出しは、設定した組織（`dev.azure.com/<org>`
またはオンプレミスの Azure DevOps Server）に直接送られます。サードパーティのサーバーを経由することはありません。

呼び出しが行われるのは次の場合です:

- PR ツールウィンドウを開いたとき（初回のリスト取得）。
- 60 秒ごとのバックグラウンド同期が実行されたとき。
- プルリクエストを開いたとき（タイムライン + 差分の取得）。
- コメントの投稿、投票、既読マーク、完了、または破棄を行ったとき。
- Azure DevOps リモートに対する `git fetch` / `git push` の資格情報受け渡しを生成したとき。
- IDE に接続した AI エージェントが Azure DevOps の MCP ツールを呼び出したとき - 下記を参照してください。

## AI プロバイダーに送信される内容 {id="whats-sent-to-ai-providers"}

AI が **有効**でプロバイダーが構成されている場合のみ送信されます。プラグインは、あなたがトリガーしたアクションに対してのみ外部への呼び出しを行います。

> AI プロバイダーを追加または編集すると、プラグインはその API キーを使用して、そのプロバイダーに対して認証済みの
> **モデルリスト**リクエスト（例: `GET /v1/models`）を 1 回行い、モデルのドロップダウンを埋めます。これは、トリガーしたアクションではなくセットアップ時に発行される唯一の
> AI リクエストです。PR のコード、差分、プロンプトは送信されず、送られるのはモデルリストの呼び出しだけで、結果は約 30
> 分間キャッシュされます。ローカルプロバイダー（localhost アドレスの Ollama）は、これをあなたのマシン内に留めます。
> {style="note"}

### 機能ごとのデータフロー

| 機能                    | プロバイダーが参照する内容                                                                             |
|-------------------------|--------------------------------------------------------------------------------------------------------|
| **Summarize PR**        | PR のタイトル + 説明 + 差分（**Max diff size**、既定 200 KB に切り詰め）。                             |
| **AI review pass**      | 変更された各ファイルのファイル単位の完全な差分。**Max diff size** を超えるファイルはスキップされます。 |
| **Explain code**        | 選択したファイルの内容（表示範囲だけでなくファイル全体）。                                             |
| **Commit message**      | ステージング済みの差分（`git diff --cached` が生成するもの）。                                         |
| **Title & description** | ブランチ名 + コミットメッセージ + 差分（上記のとおり切り詰め）。                                       |

差分はIDEを出る前に事前フィルタリングされます:
ロックファイル、ミニファイ済み・自動生成ファイル、バイナリ、ビルド出力フォルダーは取り除かれます。リネームされたファイルは実際の編集分のみが含まれ、削除されたファイルは内容の代わりに1行のメモ（パスと削除された行数）だけが含まれます。

各 AI リクエストには、プラグインがその機能向けに構築するシステムプロンプトも含まれます。これらのプロンプトは <ui-path>
Settings | Tools | DevOps Lens | AI Settings | Configure Prompts</ui-path> で上書きできます。

### プロバイダーのデータフロー一覧

| プロバイダー           | リクエストの送信先                                                                                                               |
|------------------------|----------------------------------------------------------------------------------------------------------------------------------|
| **Claude (Anthropic)** | `api.anthropic.com`（またはカスタムのベース URL）。                                                                              |
| **OpenAI**             | 既定では `api.openai.com`、または構成したベース URL（Azure OpenAI、vLLM、セルフホスト）。                                        |
| **Gemini (Google)**    | Google の AI Studio / Vertex AI のエンドポイント。                                                                               |
| **Ollama**             | 設定したエンドポイント、通常は `http://localhost:11434`。これが localhost アドレスの場合、**ネットワークへの送信はありません**。 |
| **Claude Code CLI**    | `claude` バイナリが認証とルーティングを処理します。データフローは Anthropic の CLI 規約によって制御されます。                    |
| **OpenAI Codex CLI**   | `codex` バイナリの認証とルーティング。                                                                                           |
| **GitHub Copilot CLI** | `copilot` バイナリはあなたの Copilot サブスクリプションを使用します。データフローは GitHub Copilot の規約に準拠します。          |

プラグインは、これらのリクエストにヘッダー、テレメトリ、分析を追加しません。上流のプロバイダーが参照する内容は、プラグインが送信した内容とまったく同じです。

## MCP エージェントが参照できるもの {id="what-an-mcp-agent-can-see"}

IDE 内蔵の MCP サーバーに AI エージェント (Claude Code、Codex CLI、Copilot CLI など) を接続すると、プラグインは Azure DevOps
ツールを提供します。これは上記までとは逆方向です。*プラグインが* AI プロバイダーへ何かを送信することはありません。エージェントが要求し、プラグインが
**あなたの** 既存の接続で **あなたの** Azure DevOps 組織に問い合わせ、その結果をエージェントに返します。その後の扱いはエージェント自身のモデルと規約に従います。

- **トークンが共有されることはありません。** ツールは認証済みクライアントを使って IDE 内で実行されます。エージェントが受け取るのは結果であって資格情報ではありません。
- **新しい送信先はありません。** これらの呼び出しは、このページの他のリクエストと同じ Azure DevOps 組織に送られます。
- **エージェントが読み取れるもの**: 接続中のリポジトリについて、プルリクエストの詳細、コメントスレッド、変更ファイル、差分そのもの、マージチェック、パイプライン、実行、失敗ログとステップログ、テスト結果。エージェントが読み取った内容は、そのモデルへ渡される可能性があります。
- **許可するまでできないこと**: コメント、投票、スレッドの解決、パイプラインの実行・キャンセル、ステージの再実行は、<ui-path>Settings | Tools | DevOps Lens | AI Settings</ui-path> の **Let AI agents change Azure DevOps** をオンにするまで無効です。
- **決してできないこと**: プルリクエストの完了・破棄、パイプライン承認ゲートの決定。

IDE の MCP サーバーにエージェントを接続していない場合、この節の内容はすべて当てはまりません。[](MCP-Tools-ja.md)を参照してください。

## AI レスポンスのキャッシュ {id="caching-ai-responses"}

機能が結果を返すと、プラグインは次のキーでキャッシュします:

- PR ID。
- リクエスト時点の差分の SHA。
- 単調増加する `cacheGeneration` カウンター - プロンプトを編集したり、プロバイダーを変更したり、サマリーカードの歯車ポップアップで
  **Clear cached AI responses** をクリックすると加算されます。

キャッシュヒットの場合、外部への呼び出しなしで即座に結果が返されます。キャッシュされたレスポンスは IDE
ローカルの状態に保存され、プラグインのアンインストール時にクリアされます。

## テレメトリ

このプラグインは **使用状況の分析を一切収集しません**。どの機能を使ったか、プルリクエストを何回開いたか、何をクリックしたかを追跡するものはありません。「phone
home」ping もなく、上記に列挙した Azure DevOps および AI プロバイダーへのリクエスト以外に、バックグラウンドでマシンから送信される呼び出しはありません。

唯一の例外がクラッシュレポートですが、これはプラグインではなく IDE 自身の機能です。詳しくは以下をご覧ください。

## クラッシュレポート {id="crash-reports"}

### この仕組みが存在する理由 {id="why-this-exists"}

プラグインがバグに遭遇したとき、役に立つ証拠であるスタックトレースはログファイルに記録されます。それを issue
に貼り付けるには、自分でファイルを探し、開き、読み、機密情報を消す必要があります。実際にそこまでする人はほとんどいないため、多くの報告は「ときどき差分が空になる」といった内容で届き、たいていは修正できません。

クラッシュレポートはこの手順をワンクリックに短縮し、実際の修正を可能にします。これはトラッキングのための仕組みではなく診断のための仕組みです。プラグインが実際に予期しないエラーをスローしたときにのみ動作します。

### 送信するのは誰か {id="who-sends-it"}

**プラグインではなく、あなたの IDE です。** DevOps Lens のクラッシュレポートは JetBrains IDE
自身の機能です。IDE がレポートを組み立てて JetBrains Marketplace に送信し、Marketplace
がそれをプラグイン開発者に届けます。プラグインはこのサービスに登録しているだけで、コードを一切提供していません。レポートに何かを追加することも、内容をフィルタリングすることも、送信を止めることもできません。

### 発生するタイミング {id="when-it-fires"}

プラグインが未処理の例外をスローすると、IDE が標準のエラーダイアログ（ステータスバーの赤いアイコン）を表示することがあります（安定版ビルドは EAP 版よりもプラグインのエラーについて控えめです）。そのダイアログには
**Report to the Third-Party Plugin** ボタンと、押した場合に何が起きるかを説明する JetBrains
の通知が表示されます。ダイアログを閉じた場合は何も送信されません。

ただし例外があります。IDE の **自動例外レポート**（有効にしない限りオフの JetBrains のデータ共有設定）をオンにしている場合、IDE
はダイアログを表示せずに自動でレポートを送信することがあります。

想定内の失敗がこの経路に達することはありません。オフライン、期限切れのトークン、403、ファイルが存在しない、といったものはすべて処理されローカルに記録されます。これらはバグではないため、クラッシュレポートが生成されることはありません。

### 送信される内容 {id="what-is-sent"}

| 含まれるもの             | 詳細                                                                                                                                                                                       |
|--------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| スタックトレース         | クラス名、メソッド名、ファイル名、行番号 - 失敗したコードパス。そのままの形で送信されます                                                                                                  |
| エラーメッセージ         | 失敗したコードが生成したテキスト。そのままの形で送信されます                                                                                                                               |
| あなたの説明             | ダイアログのコメント欄に入力した場合、その文章のみ                                                                                                                                         |
| プラグインのバージョン   | 例: `1.4.2`                                                                                                                                                                                |
| IDE 名とビルド           | 例: `IntelliJ IDEA 2026.2 (Ultimate Edition), build IU-262.9437.185`                                                                                                                       |
| オペレーティングシステム | 名称、バージョン、アーキテクチャ、CPU 数                                                                                                                                                   |
| Java ランタイム          | IDE のブート JVM のビルドとベンダー。例: `21.0.5+8-b631.28 (JetBrains s.r.o.)` - 描画やアイコンの不具合のいくつかは JetBrains Runtime のバグであり、IDE のバージョンだけでは特定できません |
| 直前の IDE アクション    | エラーの直前に実行したアクションの識別子                                                                                                                                                   |
| インストール済みプラグイン | バンドルされていないプラグインの識別子                                                                                                                                                    |
| インストール識別子       | IDE がエラーレポート用に生成する固定の識別子。氏名やメールアドレスは含まれません                                                                                                           |

### フィルタリングされない内容 {id="what-is-never-sent"}

レポートは IDE のものであるため、プラグインが内容を秘匿処理することはできません。実際には次のとおりです。

- **あなたのコードは含まれません。** ファイルの内容、差分、コメントの文面、プルリクエストのタイトルや説明は含まれません。そもそもプラグインがそれらを例外に入れないためです。
- **プラグインが資格情報をエラーメッセージに入れることはありません。** 個人用アクセストークン（PAT）、OAuth トークン、AI の API
  キーは IDE のパスワードストアに保管され、スタックトレースが到達できる場所にはありません。
- **業務を識別できる名前が現れる可能性があります。** エラーメッセージが組織名、プロジェクト名、リポジトリ名、サーバーのホスト名を含むことがあり、入出力エラーではファイルパスが現れることもあります。送信時にそれらを取り除く処理はありません。
- **コメント欄に入力した内容はそのまま送信されます。** コード、資格情報、チケットの内容、機密性のある名称を貼り付けないでください。

自分で内容を確認してから送りたい場合は、ダイアログではなく下記の診断スナップショットを使ってください。正式な法的記述は[英語版プライバシーポリシー](%docs_url%privacy-policy.html#crash-reports)にあります。

### 先に自分で読めるスナップショット {id="anonymization-happens-on-your-machine"}

<ui-path>Help | Copy DevOps Lens Diagnostics</ui-path> は、プラグイン自身が組み立てる唯一のレポートであり、あなたやあなたの業務を識別できない値だけで構成されています。

- プラグイン、IDE、OS、Java のバージョン
- 設定済みアカウントの **数** と、それが `cloud` / `on-prem` / その両方のいずれか - サーバーアドレスは含まれません
- プラグインが現在オンラインと判断しているかどうか
- キャッシュのカウンター（エントリ数やヒット率）。キャッシュの中身は含まれません

出力はクリップボードに置かれるだけなので、誰よりも先にあなたが内容を確認し、貼り付け先を選べます。背後で秘匿処理は行われませんが、その必要もありません。組織名、プロジェクト名、リポジトリ名、サーバー名、ユーザー名にあたる値は、そもそも収集していないからです。

### 送信先 {id="where-it-goes"}

レポートは **JetBrains Marketplace** に送られ、Marketplace
がそれをこのプラグインの Exception Analyzer ページに振り分けます。閲覧できるのはプラグイン開発者です。公開の issue トラッカーに投稿されることは
**なく**、一般に公開されることもありません。

このサービスを運営し、レポートを最初に受け取るのは JetBrains s.r.o. です。その利用範囲は
[JetBrains Exception Analyzer の規約](https://www.jetbrains.com/legal/agreements/exception_analyzer.html)（IDE
がダイアログ下の通知からリンクしています）に定められています。開発者は Marketplace の画面を通じてレポートを読みます。

プラグイン開発者が運用するサーバーは、ここにも他のどこにも存在しません。プルリクエスト、コード、資格情報、AI はすべて、あなたの
IDE と、あなた自身の Azure DevOps 組織またはあなた自身の AI
プロバイダーとの間で直接やり取りされます。正式な法的記述は[英語版プライバシーポリシー](%docs_url%privacy-policy.html#crash-reports)にあります。

### 何も送信したくない場合 {id="if-you-would-rather-not-send-anything"}

エラーダイアログを閉じれば、マシンから何も送信されません。IDE の **自動例外レポート**
を有効にしている場合は、それもオフにしてください。確認なしにレポートを送信し得るのはその設定です。

それでもバグを修正してほしい場合は、<ui-path>Help</ui-path> メニューの <b>Copy DevOps Lens Diagnostics</b>
を使い、その内容を自分で確認したうえで[公開 issue](%new_bug_url%)
に貼り付けてください。[問題を報告する](Troubleshooting-ja.md#reporting-a-problem)を参照してください。

チーム全体でこの経路を閉じたい管理者は、IDE のデプロイ設定から IDE のエラー報告ダイアログを無効化できます。ダイアログがなければ、押すボタンもありません。

## すべてをローカルに保つ

データレジデンシー要件のある組織向け:

1. **オンプレミスの Azure DevOps Server**（旧称 TFS）を使用する。プルリクエスト、コメント、API のすべてが自社サーバー上に存在します。
2. マスタースイッチで **AI を無効化する**、または `localhost` で稼働する **Ollama インスタンスにすべての AI
   機能をルーティングする**。オフライン対応のモデル（Llama、Mistral など）と組み合わせれば、データはマシンから一切外に出ません。
3. サードパーティ CLI の規約を引き継ぎたくない場合は、 **CLI 系の AI プロバイダーを避ける**。便利ですが、そのデータフローはプラグインからは不透明です。

## カスタム AI プロバイダー（エンタープライズ） {id="custom-ai-providers-enterprise"}

%product% は拡張ポイントを公開しており、エンタープライズの社内プラグインが組み込みの AI 実装を置き換え、たとえば社内ゲートウェイ経由で
AI 呼び出しをルーティングできます。拡張ポイントは `plugin.xml` の名前空間 `intellij.vcs.azuredevops`
の下で宣言されています。実装の詳細については、プラグインの GitHub リポジトリを参照してください。

より優先度の高い拡張が登録されている場合、その機能についてはプラグインの組み込みの既定が回避されます。
