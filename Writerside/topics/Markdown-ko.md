# Markdown

<tldr>
    <p><b>위치</b>: 모든 작성기 - 댓글, 답글, PR 설명, Create-PR 폼.</p>
    <p><b>구문 참조</b>: 작성기 맨 아래 행의 <b>Markdown is supported</b> 링크가 Microsoft의 Azure DevOps 마크다운 지침을
       엽니다.</p>
</tldr>

플러그인에서 작성하는 모든 것은 **Azure DevOps 방언의 마크다운**이며, 읽는 모든 것은 플러그인이 직접 렌더링합니다. 게시된 댓글, 스레드 답글, **Preview** 탭, PR 설명이 모두 같은
파이프라인을 지나므로 미리 본 그대로 게시됩니다.

## 모든 작성기에 있는 구문 링크

작성기 맨 아래 행에는 **Add files** 왼쪽에 은은한 **Markdown is supported** 링크가 있습니다.

<deflist>
    <def title="GitHub이 아니라 Microsoft의 지침을 엽니다">
        클릭하면
        <a href="https://learn.microsoft.com/en-us/azure/devops/project/wiki/markdown-guidance?view=azure-devops">Syntax
        guidance for basic Markdown usage</a>가 브라우저에서 열립니다 - 지금 입력하는 내용에 실제로 적용되는 참조입니다. 두 방언은 중요한
        지점에서 다릅니다. Azure DevOps에는 자체 이미지 크기 확장, 자체 이모지 세트, 그리고 wiki 전용으로 남겨 둔 구문이 있습니다
        (<a anchor="wiki-only">아래</a> 참고).
    </def>
    <def title="Write와 Preview 모두에서 유지됩니다">
        모드가 아니라 필드를 설명하는 링크이고, 렌더링 결과를 확인하는 Preview야말로 구문 참조가 필요한 곳입니다.
    </def>
    <def title="너비를 가장 먼저 양보합니다">
        작성기의 맨 아래 행은 반응형입니다. 좁은 화면 - 좌우로 분할된 diff의 한쪽, 폭을 줄인 도구 창 - 에서는 이 링크가 먼저 아이콘만 남고 이어서 완전히 사라집니다.
        <b>Add files</b>가 자기 레이블을 포기하기 전입니다. 제출 버튼은 절대 줄어들지 않으므로 어떤 너비에서도 <b>Comment</b> / <b>Reply</b>는 클릭할 수
        있습니다. 링크가 사라져도 잃는 것은 없습니다 - 문서로 가는 지름길일 뿐이고, 같은 페이지는 브라우저에서 한 번의 클릭으로 열립니다.
    </def>
</deflist>

## 렌더링되는 구문

| 구문                  | 입력                                                | 참고                                                                                      |
|-----------------------|-----------------------------------------------------|-------------------------------------------------------------------------------------------|
| **제목**              | `# H1` … `###### H6`                                | `#` 뒤의 공백은 선택 사항입니다 - `#Heading`도 동작합니다. [아래 참고](#hash)를 보세요.  |
| **강조**              | `**bold**`, `_italic_`, `~~strikethrough~~`         | 취소선 안의 중첩 강조도 유지됩니다.                                                        |
| **목록**              | `-` / `*` / `1.`, 들여쓰기로 중첩                   |                                                                                             |
| **작업 목록**         | `- [ ] open`, `- [x] done`                          | ☐ / ☑ 글리프로 표시됩니다. 상태를 보여줄 뿐 클릭할 수 있는 체크박스는 아닙니다.            |
| **표**                | 파이프로 구분한 셀과 `---` 구분 행                  | 실제 셀 테두리와 함께 그려집니다.                                                          |
| **링크**              | `[text](url)`, 맨 URL, `[text](#anchor)`            | `http`, `https`, `mailto`만 열립니다. 다른 스킴은 실행되지 않고 무시됩니다.                |
| **이미지**            | `![alt](url)`, `![alt](url =500x250)`               | Azure의 `=WxH` 접미사도 받아들입니다. 어느 쪽이든 이미지는 열 너비에 맞게 조정됩니다.       |
| **코드**              | `` `inline` `` 과 ``` ``` ``` 펜스                  | 펜스 블록은 실제 IDE 하이라이팅을 받습니다 - [아래](#code-blocks) 참고.                    |
| **인용**              | `> quoted`                                          | **Quote reply**가 삽입하는 형식입니다.                                                     |
| **구분선**            | `---`                                               |                                                                                             |
| **이모지**            | `:tada:`, `:+1:`, `:rocket:`                        | 약 270개의 일반적인 단축코드. 모르는 것은 그대로 남고, `\:tada:`로 이스케이프합니다.        |
| **이스케이프**        | `\*not italic\*`                                    |                                                                                             |

> `$a^2 + b^2$` 수식은 조판되지 않고 **코드 스팬**으로 표시됩니다. Azure DevOps는 브라우저 수식 엔진으로 렌더링하지만 IDE의 렌더링 패널에는 그에 해당하는 것이
> 없습니다. 그래서 본문 속에 조용히 흘려보내는 대신 원본 그대로 보여 줍니다.
> {style="note"}

## 사람과 작업 항목 참조

다음 세 가지 참조 형식은 Azure DevOps 고유의 것이며, 세 가지 모두 입력하는 동안 자동 완성됩니다.

| 유형 | 삽입             | 렌더링 결과                                                     |
|------|------------------|-----------------------------------------------------------------|
| `@`  | `@<user>`        | 표시 이름. 클릭하면 작성자 카드가 열립니다.                     |
| `#`  | `#1234`          | 해당 작업 항목 링크. 브라우저의 Azure Boards에서 열립니다.      |
| `!`  | `!567`           | 해당 풀 리퀘스트 링크. IDE 안에서 열립니다.                     |

그 뒤의 선택기는 [](Discussions-and-Comments-ko.md#work-items)를 참고하세요.

### `#1234` 작업 항목 참조 {id="hash"}

`#` 뒤에 작업 항목 ID를 붙인 것이
[Azure DevOps의 작업 항목 참조](https://learn.microsoft.com/en-us/azure/devops/boards/backlogs/add-link?view=azure-devops)
입니다 - `#` 선택기가 삽입하는 것과 같은 토큰이고, Azure DevOps 웹 UI가 풀 리퀘스트 설명에서 알아듣는 것과도 같은 토큰입니다. 댓글이나 설명에 `Fixes #1234`라고 쓰면
`#1234`가 Azure Boards에서 그 작업 항목을 여는 링크로 렌더링됩니다.

> **줄 맨 앞의 `#1234`는 제목이 아니라 참조입니다.** `#` 뒤에 숫자가 오면 줄 맨 앞이라도 작업 항목 참조로 읽히므로 `#404 Not found`는 작업 항목 404를 링크합니다.
> 숫자로 시작하는 제목을 쓰려면 공백을 넣은 표준 형식 - `# 404 Not found` - 을 사용하세요. 글자로 시작하는 붙여 쓴 제목(`#Overview`)은 영향을 받지 않습니다.
> {style="note"}

이것이 **하지 않는** 두 가지도 알아 둘 만합니다.

- **참조를 렌더링하는 것과 작업 항목을 연결하는 것은 다릅니다.** Azure Boards가 추적하는 연결을 만드는 것은 PR 사이드바의 **Work items** 행 (그리고 Create 폼의
  **Work items** 필드)에 있는 링크입니다. 설명에 `#1234`를 입력하면 클릭할 수 있는 참조가 생길 뿐, IDE에서 그 행이 채워지지는 않습니다.
- **커밋 메시지는 서버의 몫입니다.** Azure DevOps는 메시지에 `#1234`가 담긴 커밋을 *푸시할* 때 작업 항목 링크를 만듭니다 -
  [](Git-Integration-ko.md#commit-refs)를 참고하세요. 플러그인은 그런 참조를 추가하지도, 고쳐 쓰지도 않습니다.

## 코드 블록 {id="code-blocks"}

펜스에 언어를 지정하면 해당 블록은 **IDE 자체의 구문 하이라이팅**으로 렌더링됩니다 - 편집기에서 그 파일 형식에 쓰이는 것과 같은 색입니다.

````
```kotlin
fun greet(name: String) = "Hello, $name"
```
````

렌더링된 블록은 네이티브 IDE 코드 블록 외형을 갖고, 오른쪽 위에 작은 배지가 붙습니다. 평소에는 언어 이름이고, 포인터가 블록 위 어디에든 있으면 **Copy code**
버튼이 됩니다. 작성기에서는 Preview로 전환하기 전에도 펜스가 **입력하는 동안** 하이라이팅됩니다.

역할이 있는 코드 블록도 있습니다. ```` ```suggestion ```` 블록은 작성자가 한 번의 클릭으로 적용할 수 있는 **Suggested change** 카드로 렌더링됩니다.
[변경 제안](Discussions-and-Comments-ko.md#suggested-edits)을 참고하세요.

## 입력 중 자동 완성

작성기는 다섯 가지를 인라인으로 완성합니다. 공백 뒤에 트리거를 입력하고, 계속 입력해 목록을 좁힌 뒤 화살표 키와 <shortcut>Enter</shortcut>로 선택하세요.

| 트리거        | 완성 대상                                                                                              |
|---------------|--------------------------------------------------------------------------------------------------------|
| `@`           | 조직 내 사람.                                                                                           |
| `#`           | 작업 항목. `#<id>`가 삽입되며 [Boards 링크](#hash)로 렌더링됩니다.                                      |
| `!`           | 풀 리퀘스트.                                                                                            |
| `:`           | 이모지 단축코드. Azure DevOps가 저장하는 형식인 단축코드(`:tada:`)가 삽입됩니다.                        |
| ```` ``` ```` | 코드 펜스 언어. IDE에 실제로 있는 파일 형식에서 가져오며 각 행에 고유 아이콘이 붙습니다.                |

> `:` 하나만으로도, `10:30` 같은 시각으로도 이모지 목록은 열리지 않습니다. ``` 하나만 (보통 *닫는* 펜스) 입력해도 언어 목록은 열리지 않습니다.
> {style="tip"}

## Azure DevOps가 wiki 전용으로 두는 것 {id="wiki-only"}

Microsoft의 지침은 wiki, PR 댓글, 그 밖의 화면을 한 페이지에서 다루며 어떤 구문이 어디에서 동작하는지 표시합니다. 다음은 **wiki 전용**입니다 - Azure DevOps도 풀
리퀘스트 댓글에서는 렌더링하지 않으므로 플러그인도 마찬가지입니다.

- `[[_TOC_]]` 목차
- Mermaid 다이어그램
- `:::` 접이식 섹션
- 삽입된 동영상
- Azure Boards 쿼리 결과
- 원시 HTML 태그
