# FAQ

%product%
を使うべきか、どう使うかといった判断に関する質問をまとめています。「壊れている、どうやって直す?」という質問については、[](Troubleshooting-ja.md)
を参照してください。

## 対応しているもの {id="compatibility"}

### このプラグインは Azure DevOps Server (オンプレミス)をサポートしていますか?

はい。アカウントを作成する際にサーバーの URL を追加してください。Azure DevOps Server 2019 以降と Azure DevOps Services
(クラウド)の両方がサポートされています。

クラウド版は `dev.azure.com/<org>` を使用します。オンプレミス版では、コレクション URL
(`https://tfs.contoso.com:8080/tfs/my-collection`)とリポジトリ URL (`…/my-collection/my-project/_git/my-repo`)
のどちらでも使用できます。どちらも同じアカウントに解決されます。PAT 認証は両方の製品で動作します。Microsoft Entra 経由の
OAuth は **クラウド専用**であるため、オンプレミスのサーバーが解決された場合、 **Log In via Microsoft…**
ボタンは非表示になるのではなく、説明付きでグレーアウトされて表示されます。

詳しい手順は、[Azure DevOps Server (オンプレミス)](Authentication-ja.md#on-prem)を参照してください。

### Azure Pipelines をサポートしていますか?

はい。専用の **Pipelines**
ツールウィンドウで、パイプラインと実行を閲覧したり、インタラクティブなステージグラフを見たり、色分けされたステップログを読んだり、手動承認ゲートを承認または却下したりできます。これらはすべて
IDE 内で完結します。プルリクエストの CI チェックが Azure ビルドを指している場合、 **Details…** をクリックすると、その実行がブラウザではなく
IDE 内で開きます。

![実行のナビゲーションバーと定義一覧を備えた Pipelines ツールウィンドウ](pipelines-tool-window-ja.png){ width="720" border-effect="line" thumbnail="true" }

Pipelines は常に有効です。最初にオンにする必要も、オフにするスイッチもありません。リポジトリが Azure DevOps のリモートに対応した時点でツールウィンドウが表示されます。邪魔されたくない場合は、<ui-path>Settings | Tools | DevOps Lens | Pipelines</ui-path> の **Refresh pipeline
runs in the background**
のチェックを外してください。ポーリング・バルーン・ストライプのバッジが止まり、ウィンドウは必要なときのために残ります。[](Pipelines-ja.md)
を参照してください。

### 従来の TFVC (Git 以外)リポジトリで動作しますか?

いいえ。このプラグインは Git ベースの Azure Repos 専用です。 **TFVC**(Team Foundation Version Control、Azure DevOps における
Git の前身であるマイクロソフトの集中型 VCS)はサポートされていません。

### Azure DevOps アカウントなしで使えますか? {id="can-i-use-this-without-an-azure-devops-account"}

いいえ。このプラグインは Azure DevOps 専用です。

### Azure Repos Wiki をサポートしていますか?

いいえ。このプラグインはプルリクエストに範囲を限定しています。Wiki の編集には Azure DevOps の Web UI を使用してください。

## サインイン {id="signing-in"}

### OAuth と PAT のどちらを選ぶべきですか?

| 使うべきもの… | 状況                                                                                                                        |
|---------------|-----------------------------------------------------------------------------------------------------------------------------|
| **OAuth**     | クラウド版(`dev.azure.com`)を使用していて、組織が OAuth を禁止しておらず、MFA プロンプトをインラインで表示したい場合。      |
| **PAT**       | Azure DevOps Server(オンプレミス)を使用している、組織のポリシーで PAT が必須、または OAuth ハンドラーの問題に遭遇した場合。 |

OAuth トークンは自動的に更新されます。PAT は作成時に設定した日付で期限切れになります。PAT は設計上 MFA をバイパスします。PAT
を生成するにはユーザーが既に認証済みである必要がありますが、トークン自体は再度プロンプトを表示しません。

### PAT はどうやって作成しますか?

<procedure title="Personal Access Token を作成する">
    <step>ブラウザーで Azure DevOps 組織にサインインします。</step>
    <step>プロフィール画像をクリック → <ui-path>User settings | Personal access tokens</ui-path> を開きます。</step>
    <step><b>New Token</b> をクリックして名前と有効期限を設定し、[](Permissions-ja.md) に記載されたアプリ必須スコープを選択します。無制限アクセスは必要ありません。</step>
    <step><b>Create</b> をクリックしてトークンをコピーします - 表示されるのは一度だけです。</step>
</procedure>

トークンは自分だけのものにしてください。チャットやチケット、ソース管理に貼り付けず、漏えいした場合は Azure DevOps で失効させます。各機能に必要なスコープは[](Authentication-ja.md)
を参照してください。

### ファイルを閲覧済みにすると 401 が返ります - トークンが間違っていますか?

DevOps Lens は最初にローカルへ記録するため、Azure が非公開の閲覧済み状態エンドポイントを拒否してもレビューは続けられます。サーバーとの同期はベストエフォートです。401 は、利用中の Azure DevOps バージョンまたは組織が、スコープ付き資格情報にその内部エンドポイントを公開していないことを示す場合があります。この機能だけのためにトークンの権限を広げないでください。PR を更新し、アカウント自体の期限切れで他の要求も失敗する場合にだけ再度サインインします。ローカルの閲覧済み状態については [](Code-Review-ja.md) を参照してください。

### プラグインがトークンを保存・読み取りできません。どうすればよいですか?

トークンは、OS のキーチェーンに支えられた IDE
のパスワードストアに保存されます。ネイティブの資格情報ストレージが無効化されているか破損している場合は、<ui-path>
Settings | Appearance &amp; Behavior | System Settings | Passwords</ui-path> を開き、KeePass
ファイルに切り替えるか既存のパスワードをクリアしてから、再度ログインしてください。期限切れトークンやスコープ不足など、その他のサインインエラーは[](Troubleshooting-ja.md)
を参照してください。

## プライバシーと AI {id="privacy-and-ai"}

### 私のコードは Azure DevOps 以外の場所に送信されますか? {id="is-my-code-sent-anywhere-other-than-azure-devops"}

AI
機能を明示的に有効化してプロバイダーを設定していない限り、送信されません。機能ごとの完全なデータフローについては、[](Privacy-and-Data-ja.md)
を参照してください。

AI が無効 (マスタースイッチがオフ)の場合、プラグイン自体は Azure DevOps 組織以外への送信を一切行いません。

別途知っておくべき点として、IDE 内蔵の MCP サーバーに AI エージェントを接続した場合、そのエージェントはあなたの接続を通じてプルリクエストやパイプラインの内容を読み取り、自身のモデルに渡すことができます。これはプラグインではなくエージェントの通信であり、そのようなエージェントを自分で設定した場合にのみ発生します。[](MCP-Tools-ja.md)を参照してください。

### AI 呼び出しを一切行わずにプラグインを使うにはどうすればよいですか?

<ui-path>Settings | Tools | DevOps Lens | AI Settings</ui-path> の上部にある **Enable AI features** のチェックを外してください。すべての AI アフォーダンスがメニューやツールバーから消え、AI 呼び出しは行われません。

また、AI をオンのままにして、すべての機能をローカルの **Ollama** インスタンスにルーティングし、完全にオンデバイスで推論を行うこともできます。

さらに、AI エージェントが IDE 経由で Azure DevOps を読み取ることも避けたい場合は、バンドルされた **MCP Server** プラグインを無効にしてください (<ui-path>Settings | Plugins</ui-path>)。そうすると Azure DevOps ツールはそもそも登録されません。

### MCP ツールを使うとプラグインの AI レビューは賢くなりますか?

いいえ。両者は無関係で、よくある誤解です。プラグイン自身の AI 機能 (要約、レビュー、コミットメッセージ) は一度きりのテキスト生成であり、ツールを呼び出すことはできません。MCP ツールは逆方向です。*あなたが* 接続したエージェント (Claude Code、Codex CLI、Copilot CLI) が、IDE を通じて Azure DevOps のデータを読み取れるようにするものです。[](MCP-Tools-ja.md)を参照してください。

### プラグインは何かを匿名でアップロードしますか? テレメトリはありますか?

使用状況分析は一切行いません。どの機能を使ったか、何をクリックしたかを記録するものはなく、バックグラウンドでアップロードされるものもありません。送信先は
Azure DevOps 組織と、AI が有効な場合は設定した AI プロバイダーだけです。(MCP 経由で接続した AI エージェントは、そのエージェント自身の規約のもとで独自に通信します。プラグインがそれらにテレメトリを追加することもありません。)

唯一の例外は **クラッシュレポート** です。プラグインが予期しないエラーに遭遇すると、IDE のエラーダイアログに
**Report to the Third-Party Plugin** ボタンが表示され、IDE がそのレポートを JetBrains Marketplace
経由でプラグイン開発者に送信します。コードが含まれることはなく、公開リポジトリに送られることもありません。ダイアログを閉じれば何も送信されません（IDE
の自動例外レポートを有効にしている場合を除きます）。レポートを組み立てるのはプラグインではないため秘匿処理はできず、エラーメッセージが組織名やリポジトリ名を含むことがあります。[クラッシュレポート](Privacy-and-Data-ja.md#crash-reports)
を参照してください。

## プラグインの使い方 {id="using-the-plugin"}

### PR のメトリクスはどこで確認できますか?

[統計](Statistics-ja.md)タブには、KPI とチャート (マージまでの時間、レビュー速度、投票の分布など)
が表示されます。これらはキャッシュされたデータからローカルで計算されます。これは表示専用のダッシュボードです。エクスポート可能な組織全体のレポートには
Azure DevOps Analytics を使用してください。

### IDE を再起動すると PR のタブが復元されないのはなぜですか?

%product% が意図的に閉じているからです。タイムライン、ファイルごとの差分、統計、パイプライン実行の各タブはセッション限定のビューであり、IDE
が復元できるものはディスク上に存在しません。そのまま残しておくと、次回起動時にタブごとにエラーが表示されるだけになってしまいます。

失われるものはありません。初回と同じように、ツールウィンドウから (または <shortcut>⌘⇧P</shortcut> / <shortcut>
Ctrl+Shift+P</shortcut> で)プルリクエストを開き直してください。通常のソースファイルのタブはそのままです。

## サポートを受ける {id="getting-help"}

### バグの報告や機能のリクエストはどこにすればよいですか?

公開トラッカー [%tracker_url%](%tracker_url%) です。壊れている場合は[バグ報告フォーム](%new_bug_url%)
、足りない機能は[機能リクエストフォーム](%new_feature_url%)、どちらか判断がつかない場合は [Discussions](%discussions_url%)
をご利用ください。

いちばん速いのは <ui-path>Settings | Tools | DevOps Lens</ui-path> の下部にある **Report a bug** です。IDE
のビルド、プラグインのバージョン、OS
が入力済みの状態でフォームが開きます。何を書けばよいか、どのくらいで返ってくるかは[](Support-ja.md)を参照してください。

セキュリティに関する問題は公開 issue ではなく、ベンダーのメールアドレス宛に非公開でご連絡ください。

### このプラグインはどのように支えられていますか?

一人の開発者が構築・保守しているソロプロジェクトです。役に立ったと感じたら、JetBrains Marketplace
でのレビューが何よりの支援になります。レビューは大歓迎です。
