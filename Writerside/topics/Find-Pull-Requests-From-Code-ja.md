# コードからプルリクエストを見つける

<tldr>
    <p><b>場所</b>: 行を右クリック → <b>Open In</b> → <b>Find Pull Request</b>。ファイル全体には、行番号ガターを右クリック → <a anchor="annotate">Annotate with Pull Requests</a>。</p>
</tldr>

コードレビューが答えるのは「この変更を取り込むべきか?」です。半年後に問われるのはその逆 -
**なぜこの行はこうなっているのか?** です。%product% はその答えをエディターから返します。行を blame
し、それを持ち込んだプルリクエストを見つけ、ファイルを離れることなくその PR のディスカッション全体を開けます。

入口は 3 つあり、いずれも同じ検索の上に成り立っています。

| 知りたいこと                         | 使うアクション                     | 場所                                  |
|--------------------------------------|------------------------------------|---------------------------------------|
| **この 1 行**の背後にある PR         | **Find Pull Request**              | 右クリック → **Open In**              |
| その **URL**（どこかに貼り付けたい） | **Copy Pull Request URL for Line** | 右クリック → **Copy / Paste Special** |
| **すべての行**の背後にある PR        | **Annotate with Pull Requests**    | **行番号ガター**を右クリック          |

> 3 つとも [](Settings-ja.md)の **Find the pull request behind a line of code**
> （既定はオン）で制御されます。また、アカウントがサインインしていて、かつファイルが Azure DevOps リモートを持つ Git
> リポジトリにある場合以外は表示されないため、無関係なプロジェクトでメニューを散らかすことはありません。いずれも既定のキーボードショートカットは持ちません。[Keymap](Keyboard-Shortcuts-ja.md#rebind)
> で自分で割り当ててください。
> {style="note"}

## Find Pull Request

行にキャレットを置き、 **右クリック → Open In → Find Pull Request** を選びます。

次に何が起こるかは、検索結果によって変わります。

| 結果                      | 得られるもの                                                                                                                                                                                 |
|---------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **プルリクエストが 1 件** | そのまま **IDE 内で**開きます - 詳細ビューとタイムラインです。ポップアップもブラウザーもありません。                                                                                         |
| **プルリクエストが複数**  | *Pull requests containing &lt;短縮 SHA&gt;* というタイトルのポップアップに一覧表示されます。完了済みの PR が先、その中では新しい順です。最終行には **Open commit … in browser** があります。 |
| **プルリクエストなし**    | コミット自体がブラウザーで開きます。その行は PR より前のものか、直接プッシュで入ってきたものです。                                                                                           |

## Copy Pull Request URL for Line

同じ検索ですが、結果はクリップボードに入ります。 **右クリック → Copy / Paste Special → Copy Pull Request URL for Line**
です。`…/pullrequest/<id>` が得られ、 *Pull request URL copied* という確認が表示されます。

**Find Pull Request** との意図的な違いが 2 つあります。

- その行を持ち込んだ PR が **ない** 場合はエラーヒント（ *No pull request introduced this line*
  ）が表示されます。コミットページへ黙ってフォールバックすることは **ありません**。あなたが求めたのは PR の URL
  であり、それが存在しないからです。
- 複数結果のポップアップからは、同じ理由で *Open commit in browser* の行が省かれます。

> **Copy Link to Code とは別物です。** *Copy Link to Code*（<shortcut>⌘⇧L</shortcut> / <shortcut>Ctrl+Shift+L</shortcut>
> 、同じ **Copy / Paste Special** メニュー内）は、 **選択しているコード**へのリンクです - レビュー中の PR
> の中でも、接続中のリポジトリの任意のファイルでも使えます。 *Copy Pull Request URL for Line* はその逆の問い - **どの PR**
> がこの行を持ち込んだのか - に答えるもので、行アンカーなしで PR 自体を指します。[](Code-Review-ja.md)
> を参照してください。
> {style="note"}

## Annotate with Pull Requests {id="annotate"}

ファイル全体を見る方法です。 **行番号ガターを右クリック → Annotate with Pull Requests** - Git 自身の *Annotate with Git
Blame* が入っているのと同じメニューで、動作も同じです。行番号の横に列が現れ、1 行につき 1 エントリが表示されます。

この列が表示するのは **プルリクエストの id** - `!1234` - だけです。作成者も、日付も、SHA も表示しません。1 行につき 1
つの問いにだけ答えるので、作業中も出したままにできるほど幅が狭いままです。

- 行に **マウスカーソルを合わせる**と、サマリーカードが表示されます。状態、タイトル、作成者、ブランチ、レビュアー（アバターは最大
  5 件、その後は `+N`）が並びます。
- 行を **クリック**すると、そのプルリクエストが IDE 内で開きます。
- どのプルリクエストにも属さないコミットの行は、SHA を表示するのではなく **空欄**になります。空欄は「これを持ち込んだ PR
  はない」という、ごまかしのない答えです。
- ある行のコミットが複数の PR に属する場合、その行を最もよく説明するもの（完了済みを優先し、その中では新しい順）が表示されます。

オフにするには同じガターメニューを使います（オンの間はチェックマークが付きます）。

> **行を追加または削除すると自動的に閉じます。**
> この列は行番号をキーにしているため、行がずれる編集を行うと、すべての行が誤ったプルリクエストを指してしまいます。嘘をつくよりはと、列はオフに切り替わります。編集が終わったら再度有効にしてください。行の
> *内部*での入力は問題なく、列は開いたままです。
> {style="warning"}

ファイル全体の blame は 1 回の `git blame` とまとめての検索で行われるため、読み込み中は進行インジケーター（「Looking up
pull requests for this file…」）が表示されます。単一行のアクションははるかに軽いので、進行 UI は表示されません。

## 検索の仕組み {id="how-it-works"}

以下のすべてのエッジケースを説明するものなので、知っておく価値があります。

<procedure title="キャレットからプルリクエストまで">
    <step>プラグインがその行に対して<b>ローカルで git blame</b> を実行し、その行を最後に変更したコミットを取得します。</step>
    <step>そのコミットを含むプルリクエストを Azure DevOps に問い合わせます。1 回のリクエストで<b>2 つ</b>のクエリを発行し、1 つはそのコミットを PR の<b>ソースコミット</b>として、もう 1 つは PR の<b>マージコミット</b>として検索します。</step>
    <step>結果は重複排除され、完了済みのプルリクエストを先に、その中では新しい順に並べられます。</step>
</procedure>

両方向で問い合わせることが、完了方法を問わずこの機能を確実にしています。PR が **マージ** された場合、blame はその元のコミットの
1 つを見ます。 **squash** された場合、それらのコミットはターゲットブランチに届いていないため、blame が見られるのは squash
コミットだけです。片方のクエリだけでは履歴の半分を取り逃がしますが、両方ならマージ、squash、リベースのいずれも捕捉できます。

キャッシュは一切行いません。呼び出すたびに blame と問い合わせをやり直すため、答えは常に現在のファイルと現在のサーバーの状態を反映します。

## エッジケースとメッセージ

失敗は **キャレット位置のヒント**として表示され、バルーンやダイアログにはなりません。

| メッセージ                                                                                      | 意味                                                                                                                           |
|-------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------|
| **This line has no committed history yet**                                                      | その行はまだコミットされていません（新しく入力した行、またはステージされていない変更の一部）。参照すべきコミットがありません。 |
| **No pull request introduced this line**                                                        | コミットは存在しますが、それを含む PR がありません（直接プッシュか、PR プロセスより古い履歴）。*Copy URL* のみ。               |
| **This file isn't in a repository with an Azure DevOps remote**                                 | そのファイルは、プラグインが認識する Git リポジトリの配下にありません。                                                        |
| **This repository belongs to a different Azure DevOps organization than the connected account** | リモートが別の組織を指しています。その組織にサインインするか、アカウントを切り替えてください。                                 |
| **Connect an Azure DevOps account to look up pull requests**                                    | まだアカウントがバインドされていません。[](Authentication-ja.md)を参照してください。                                       |
| **Couldn't look up pull requests for this line**                                                | 検索の呼び出しが失敗しました。通常はオフラインか一時的な API エラーです。再試行してください。                                  |
| **This file has no committed history yet** *(ガター)*                                           | ファイル全体が未追跡か、新規作成されたものです。                                                                               |
| **No pull request introduced any line of this file** *(ガター)*                                 | すべての行が PR プロセスより古いか、直接プッシュで入ってきたものです。                                                         |

> **blame はディスク上のファイルを読みます。** キャレットより *上*に未保存の編集がある場合、プラグインが blame
> する行番号は保存済みのものになるため、誤った行に帰属させることがあります。答えがおかしいと感じたら、まず保存してください。
> {style="warning"}

> これらのアクションは、設計上 **差分ビューアー**内では使用できません。差分が表示するのは仮想ファイルであり、blame できるローカルの
> Git 履歴がないためです。通常のエディターで使用してください。
> {style="note"}

## 同じ問いを、コミットから {id="from-commit"}

ここまではすべて**行**が起点でした。代わりに**コミット**を見ているとき - Git の **Log** の行、**File History** のエントリ、または blame
列の右クリックメニュー - でも、同じ検索はメニュー項目 1 つ分の距離にあります。**Open Commit in Azure DevOps** と **Copy Azure DevOps Commit Link** の隣にある
**Find Related Pull Requests** です。

このページの行アクションとの違いは 3 つ。結果はエディターのヒントではなく通知として届くこと、設定による制御がないこと、そして行単位の検索にはできない、**まだマージされていない**プルリクエストも見つけられることです。[Git
ビューでのコミットアクション](Git-Integration-ja.md#commit-actions)を参照してください。
