# Git 連携

<tldr>
    <p><b>場所</b>: IDE のクローンダイアログ、メインツールバーとステータスバーのブランチウィジェット、IDE 内のあらゆる <code>git fetch</code> / <code>push</code>。</p>
    <p><b>動作条件</b>: Git リモートが Azure DevOps（クラウド、レガシー、SSH、または設定済みのオンプレミスサーバー）に一致すること。</p>
</tldr>

このプラグインは IDE にバンドルされている Git プラグインと連携し、Azure DevOps のリモートを検出して、現在のブランチをその
PR と対応付け、HTTPS 認証情報を引き渡すことで `git fetch` と `git push` をそのまま動作させます。

## リポジトリの検出

プロジェクトを開くと、プラグインはすべての Git リモートを走査して次のパターンを探します。

- `https://dev.azure.com/<org>/<project>/_git/<repo>`
- `https://<org>.visualstudio.com/<project>/_git/<repo>`（レガシー）
- `git@ssh.dev.azure.com:v3/<org>/<project>/<repo>`（SSH）
- アカウントに登録されたセルフホストの Azure DevOps Server の URL

いずれかのリモートが一致すると、 **Pull Requests** ツールウィンドウが表示され、バックグラウンド同期が始まります。一致しない場合、プラグインは邪魔になりません。

## リポジトリのクローン

IDE を離れずに Azure DevOps からクローンできます。

1. ようこそ画面で **Clone Repository** を選択し（プロジェクトを開いている場合は **File | New | Project from Version
   Control**）、左のリストから **Azure DevOps** を選びます。
2. まだサインインしていなければサインインします - プラグインの他の場所と同じ Microsoft またはトークンによるサインインです。
3. 入力して `project/repository` のリストを検索し、リポジトリを選択して、必要ならクローン先ディレクトリを調整します。
4. **Clone** をクリックすると、IDE が HTTPS でクローンしてプロジェクトを開きます。認証情報は、後述の「HTTPS
   認証」のとおりサインイン済みアカウントから供給されます。

### リポジトリ一覧が読み込まれない場合 {collapsible="true"}

一覧はアカウントごとに一度だけ取得され、ダイアログが開いている間は保持されるため、最初の読み込み後はアカウントを切り替えてもコストはかかりません。

| 一覧の表示                                          | 意味                                                                                           |
|-----------------------------------------------------|------------------------------------------------------------------------------------------------|
| **Loading repositories…**                           | 組織全体の一覧をまだページングして取得している最中です。                                       |
| **No repositories in this organization**            | アカウントは組織に到達できますが、その中にリポジトリが見つかりません。                         |
| **No matching repositories**                        | 検索テキストが隠しているだけです - フィールドをクリアしてください。                            |
| **Couldn't load repositories** + **Retry**          | 呼び出しが失敗しました。通常はオフラインか一時的なエラーです。                                 |
| **Couldn't access &lt;account&gt; - sign in again** | そのアカウントのトークンが機能しなくなっています。リンクからログインダイアログを開き直せます。 |

## 現在のブランチ → PR

プラグインはチェックアウトされたブランチを監視し、（ソースブランチ名によって）対応するオープンな PR に解決します。見つかると、2
つのウィジェットが点灯します。

### メインツールバーのブランチウィジェット

**main toolbar** の Git ブランチウィジェットに Azure DevOps バッジ `!1234 on feature/login` が付きます。クリックするとその
PR の操作が表示されます。

- **Show Pull Request in the Tool Window** - PR の詳細ビューを開きます。
- **Update to Enable Review Mode…** - ローカルブランチが PR のヘッドから分岐している場合に表示されます（ *Update Project*
  を実行します）。
- **Review Mode** - エディター内レビューのオーバーレイを切り替えます。[](Review-in-Editor-ja.md)
  を参照してください。

### ステータスバーのウィジェット

**status bar** にある別のウィジェットは `ADO PR !1234` を表示します。クリックするとその PR
がツールウィンドウで開きます。（ステータスバーのウィジェットチューザーで表示・非表示を切り替えられます。名前は *Azure
DevOps PR (current branch)* です。）

ブランチを切り替えると両方のウィジェットが更新され、新しいブランチに PR がない場合は消えます。

## 行の背後にあるプルリクエストを見つける {id="find-pull-request"}

ある行を眺めながら、 *なぜ*こうなっているのだろうと考えたことはありませんか? プラグインはその行をローカルで blame
し、どのプルリクエストがそれを持ち込んだのかを教えてくれます。1 回限りの検索としても、行番号の横に常設する列としても使えます。

これはそれ自体で 1 つの機能です。[](Find-Pull-Requests-From-Code-ja.md)を参照してください。

## Git ビューでのコミットアクション {id="commit-actions"}

同じ問いは、目の前にある**コミット**についても生じます。そこでプラグインは、IDE がコミットを示す場所すべてに 3 つの項目を追加します - **Git** ツールウィンドウの **Log**
タブ、**File History**（タブと **Show History for Selection** ダイアログの両方）、そして行番号の横にある blame 列、つまり**注釈ガター**の右クリックメニューです。

| アクション                        | 動作                                                                                  |
|-----------------------------------|---------------------------------------------------------------------------------------|
| **Open Commit in Azure DevOps**   | そのコミットのページを Azure DevOps の Web サイトでブラウザーに開きます。              |
| **Copy Azure DevOps Commit Link** | 同じ URL をクリップボードにコピーします。IDE 自身の *Copy Revision Number* と同じく、通知は出ません。 |
| **Find Related Pull Requests**    | そのコミットを含むプルリクエストを検索し、答えを **IDE 内**で開きます。                |

> **設定は不要です。** 上記の行単位の検索とは異なり、この 3 つに専用の設定はありません。コミットのチェックアウトが、サインイン済みアカウントの組織にある Azure DevOps
> リポジトリとして解決できない限り表示されないため、別の場所でホストされているプロジェクトのメニューが不要な項目で埋まることはありません。既定のキーボードショートカットも持ちません。[Keymap](Keyboard-Shortcuts-ja.md#rebind)
> で自分で割り当ててください。
> {style="note"}

どのコミットを対象にするかは、次の 2 点で決まります。

- **Log では、選択行がちょうど 1 つのときだけ。** 複数のコミットを選択すると項目は消えます。複数行の選択に対して「このコミットのリンク」という答えは存在せず、黙って先頭を選べば、指し示していないコミットを操作することになるからです。
- **注釈ガターでは、右クリックした行。** キャレットのある行ではありません（両者が一致することはまれです）。同じメニューにある *Copy revision number* や *Annotate revision*
  と同じ挙動です。

### Find Related Pull Requests {id="commit-find-prs"}

[Find Pull Request](Find-Pull-Requests-From-Code-ja.md) のコミット版です。検索そのものは同じで、起点が行ではなくコミットになります。これらのビューにはヒントを表示するエディターがないため、結果は通知として届きます。

| 結果                      | 表示されるもの                                                                    |
|---------------------------|-----------------------------------------------------------------------------------|
| **プルリクエストが 1 件** | すぐに IDE 内で開きます - 詳細ビューとタイムラインです。                          |
| **プルリクエストが複数**  | 右クリックした行の横に *Pull requests containing &lt;短い SHA&gt;* のチューザーが開きます。選んだものが開きます。 |
| **プルリクエストなし**    | *Commit &lt;短い SHA&gt;* バルーンが **No pull request contains this commit** と伝え、**Open Commit**（そのコミット自身のページをブラウザーで開く）を提示します。 |

> **まだマージされていないプルリクエストも見つかります。** Azure DevOps は「このコミットを含むプルリクエスト」にマージの側からしか答えられないため、オープンな PR
> のソースブランチ上にあるだけのコミット - Log で右クリックする対象は通常こちらです -
> では結果が空になります。その場合、プラグインはローカルで 2 つ目の問いを立てます。どの**リモートブランチ**がそのコミットを含むか、そしてそれらのブランチ*から*作成されたプルリクエストはどれか、です。**スカッシュマージ**されたプルリクエストは元のコミットをソースブランチにしか残さないため、ステータスは問いません。照会するブランチは最大
> 5 件で、この機能が想定するケースはこれで十分にカバーできます。
> {style="tip"}

## HTTPS 認証

Git が Azure DevOps リモートに対して HTTPS 認証情報を必要とすると、プラグインは保存されたトークンを自動的に供給します。

<procedure title="HTTPS 認証の引き渡しの仕組み">
    <step>IDE 内から（Update Project、Git ツールウィンドウ、または組み込みターミナルで）<code>git fetch</code> または <code>git push</code> を実行します。</step>
    <step>Git が IDE に認証情報を要求します。</step>
    <step>プラグインがリモートをサインイン済みのアカウントと照合し、そのトークンを供給します。</step>
    <step>Git が処理を進めます - パスワードの入力は求められません。</step>
</procedure>

同じ URL に複数のサインイン済みアカウントが一致する場合は、プロジェクトの **デフォルトアカウント**
が使用されます（[](Settings-ja.md)を参照）。

> IDE の外部の **システムシェル**から実行された Git コマンドは、このプロバイダーを認識しません。主に外部ターミナルで作業する場合は、システム全体の
> Git 認証情報ヘルパーを設定してください - [トラブルシューティング](Troubleshooting-ja.md#git-push-asks-for-a-password)
> を参照してください。
> {style="note"}

## Push → PR の作成

まだ PR のないブランチをプッシュした後、プラグインはバルーンで **Create a pull request** を提案できます -
ツールバーよりも速い経路です。[](Settings-ja.md)の **Offer to create a pull request after I push**
で切り替えられます。その他の Git
由来の通知（レビュー依頼、投票の変更、返信）は[](Notifications-and-Attention-ja.md)で扱っています。

### コミットメッセージ内の作業項目 {id="commit-refs"}

コミットメッセージに `#ID` の参照が含まれていると、Azure DevOps はそのコミットを作業項目にリンクします。
`#35 Catch null exception` としてコミットしてプッシュすると、サーバーが作業項目 35 に **Commit**
リンクを作成します。このリンク付けは **サーバー側で、プッシュ時に**
行われます。プラグインはこれらの参照を追加も書き換えもせず、動作させるために IDE
側で設定しておくものもありません。参照は普段どおりコミットメッセージに書けば十分です。

AI によるコミットメッセージ生成（[](AI-Features-ja.md)）も同じです。すでに書かれている `#ID`
は保持しますが、どの作業項目を指しているかは分からないため、自分で作り出すことはありません。

コメントやプルリクエストの説明の中の `#ID` 参照 - こちらはプラグインが実際にリンクとしてレンダリングします -
については、[](Markdown-ja.md#hash)を参照してください。

## 複数リポジトリとセルフホスト

- 1 つのプロジェクト内の **複数のリポジトリ**はそれぞれ独立して検出されます。ツールウィンドウの **Switch Account /
  Repository…** を使って 1 つに絞り込みます。
- **Azure DevOps Server（オンプレミス）**はクラウド製品とまったく同じように動作します - サインイン時にサーバー URL
  を追加し、そのサーバーで生成したトークンを使用します。
